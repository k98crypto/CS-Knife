## 一、它是什么

一个**半自动 / 全自动的游戏客服助手**，跑在你自己电脑上：

- 从客服工作台网页**实时抓取玩家工单**
- 用 AI（DeepSeek）对照**官方规章库**生成合规回复
- 电脑上按热键即可**一键出话术**，不用手打
- 手机上能**远程看工单、改状态、代回复、一键关单**

它**不改动官方系统**，只是在浏览器里"帮你操作"，所有回复最终仍由你确认发送。

## 二、系统组成

```
┌──────────────────┐        WebSocket        ┌────────────────────┐
│  probe.js        │◄───────────────────────►│ bridge_server.py   │
│  （油猴探针）      │   ws://127.0.0.1:8765   │  （中继 + 手机网页） │
│  跑在客服工作台页   │                         │  跑在本机 8765 端口  │
└──────────────────┘                          └─────────┬──────────┘
                                                         │ 调用
         ┌───────────────────────────────────────────────┤
         │                                               │
┌────────▼─────────┐                          ┌──────────▼─────────┐
│ agent_core.py    │                          │ semi_runner.pyw    │
│ 业务大脑          │                          │ 桌面悬浮窗 + 热键    │
│ 规章库 / AI 决策  │                          │ F6 F7 F8 F9 F10    │
└────────┬─────────┘                          └────────────────────┘
         │
┌────────▼─────────┐     ┌──────────────┐     ┌────────────────────┐
│ rules.xlsx│     │ DeepSeek API │     │ Bark 推送到手机      │
│ 规章库（13 张表）  │     │ 生成回复      │     │ 疑难单 / 掉线 / 关单  │
└──────────────────┘     └──────────────┘     └────────────────────┘
```

| 文件 | 作用 |
|------|------|
| `probe.js` | 油猴脚本，抓页面数据、执行回复动作 |
| `bridge_server.py` | 中继服务，同时提供手机端网页 |
| `agent_core.py` | 规章库匹配 + AI 决策 |
| `semi_runner.pyw` | 桌面悬浮窗（热键、状态提示、结果核验） |
| `launcher.py` | 一键启动（中继 + 悬浮窗） |
| `launcher.exe` | 打包好的一键启动器（双击即用，本机产物、未入库） |
| `启动服务.vbs` | 双击启动两个服务（中继带窗口、悬浮窗静默） |
| `一键打包清理.bat` | 重新打包 `launcher.exe` 并清理中间产物 |
| `rules_sync.py` | 规章库自动同步工具 |
| `distill_rules.py` | **离线工具**：把人工回复样本逆向蒸馏成话术规则（V8.3，见 7.8） |
| `config.json` | 所有配置（**含密钥，切勿外传**） |
| `rules.xlsx` | 规章库文件 |

## 三、安装与首次配置

### 3.1 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 / 11 |
| Python | 3.8 以上（本文档实测 3.14） |
| 浏览器 | Chrome / Edge，并安装 **Tampermonkey** 扩展 |
| 手机 | 与电脑在**同一个 WiFi / 局域网** |
| 网络 | 能访问 DeepSeek API |

### 3.2 安装依赖

在项目目录打开命令行：

```bash
pip install -r requirements.txt
```

如果下载很慢，用国内镜像：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 3.3 配置 `config.json`

用**记事本**或 VS Code 打开 `config.json`，逐项填写：

```json
{
  "port": 8765,
  "bark_key": "你的 Bark Key",
  "deepseek_api_key": "sk-你的DeepSeek密钥",

  "use_local_excel": true,
  "local_excel_path": "rules.xlsx",

  "rules_auto_sync": true,
  "rules_sync_interval_minutes": 30,
  "rules_watch_dir": "",

  "kb_retrieval_enabled": true,
  "kb_retrieval_top_k": 25,
  "kb_static_max_chars": 12000,
  "kb_entry_max_chars": 400,

  "close_category_path": ["一级分类", "二级分类"],
  "close_category_default": "其他"
}
```

**必填的两项**：

| 键 | 说明 | 不填会怎样 |
|----|------|-----------|
| `deepseek_api_key` | DeepSeek 开放平台的 API Key（`sk-` 开头） | **AI 完全不可用** |
| `bark_key` | iPhone 上 Bark App 里显示的 Key | 手机收不到推送（其他功能正常） |

> ⚠️ **安全提醒**：`config.json` 已加入 `.gitignore`，**不会被上传到 Git**。
> 但仍请勿通过微信/邮件外发这个文件。

### 3.4 准备规章库

把在线表格导出为 Excel，命名为 **`rules.xlsx`**，放到项目根目录（和 `launcher.bat` 同一层）。

> 当前规章库含 13 个工作表、800+ 条规则，系统会自动全部解析。

验证是否读取成功：

```bash
python rules_sync.py --info -v
```

### 3.5 安装油猴脚本

1. 浏览器点 Tampermonkey 图标 → **添加新脚本**
2. 全选删除模板内容
3. **打开 `http://127.0.0.1:8765/probe.js`**（推荐）→ `Ctrl+A` / `Ctrl+C` 全选复制
4. 覆盖粘贴到油猴编辑器里
5. `Ctrl + S` 保存，确认脚本已启用（状态为绿色）

> ⚠️ **请从 `http://127.0.0.1:8765/probe.js` 复制，不要直接打开项目目录里的 `probe.js` 复制。**
> 原因：仓库是公开的，`probe.js` 里的 `@match` 域名写成**占位符** `ticket.example.com`；
> 中继在响应 `/probe.js` 时会按本地 `config.json` 的 `workbench_domains` **自动注入你的真实工单域名**
> （可填多个，会展开成多行 `@match`）。所以从项目文件直接复制出来的脚本是**匹配不到工作台**的。

```json
"workbench_domains": ["你的工单域名", "备用域名（可省略）"]
```

> 加 `?download=1`（`http://127.0.0.1:8765/probe.js?download=1`）可以直接下载成文件。

脚本只会在上面配置的域名生效，不会影响其他网站。

> **粘贴后必须刷新工作台页面**，然后看页面**左下角有没有一个绿色小胶囊**
> `🟢 探针 v8.0 · 已连接`：
>
> - 有绿色胶囊 = 脚本已生效 ✅
> - 有红色/黄色胶囊 = 脚本生效了，但没连上中继（中继没启动，或还没刷新页面）
> - 完全没有胶囊 = 脚本没生效（油猴里没启用 / 域名不匹配 / 没保存成功）
>
> 这是判断"油猴到底加载了没"最快的办法（详见 12.2）。

## 四、启动与关闭

### 4.1 启动

**方式一：双击 `launcher.exe`（最省事，本机已打包好）**

**方式二：双击 `启动服务.vbs`（无黑框干扰）** —— 中继在窗口里跑（方便看日志），悬浮窗静默启动。

**方式三：双击 `launcher.bat`**（本机自带脚本，未入库；公开仓库里请用下面方式四），它会自动：

1. 检查 Python 环境与必要文件
2. 必要时自动安装依赖
3. 启动中继服务（黑框窗口）
4. 启动桌面悬浮窗

**方式四：命令行两行**（仓库自带的 `launcher.py` 与手动启动等价）

```bash
python launcher.py             # 一键（等价于下面两条）
# 或手动分两步：
python bridge_server.py        # 中继服务（保留窗口看日志）
pythonw semi_runner.pyw        # 桌面悬浮窗（无黑框）
```

启动成功会看到：

```
============================================================

手机访问: http://192.168.x.x:8765
系统自检: http://127.0.0.1:8765/diag   （探针/手机端是否在线一屏看懂）
探针脚本: http://127.0.0.1:8765/probe.js （核对油猴里那版是否最新 v8.0）
============================================================
[规章库] 自动同步已开启：每 30 分钟检查一次
[探针] ✅ 已连接 · 来源: https://你的工单域名/...
[探针] 🚀 握手成功：v8.0 · https://你的工单域名/imChat/workstation
```

**记住那个 `http://192.168.x.x:8765` 地址**，手机要用。

如果只看到 `[探针] ⚠️ 已连接但未上报版本`，说明油猴里还是旧脚本，按 12.2 更新即可。

### 4.2 首次启动的防火墙提示

Windows 可能弹窗询问是否允许 Python 访问网络 —— **必须勾选「专用网络」并允许**，
否则手机连不上。

若误点拒绝，手动放行：

```
控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙
→ 找到 Python → 勾选「专用」
```

### 4.3 关闭

| 想关闭的东西 | 操作 |
|-------------|------|
| 全部服务 | 关闭「CS-WebSocket」黑框窗口 |
| 只关悬浮窗 | 点悬浮窗右上角 ✕（不影响中继服务） |
| 强制全清 | 任务管理器结束所有 `python.exe` / `pythonw.exe` |

### 4.4 开机自启（可选）

```

```

## 五、电脑端日常使用

### 5.1 热键速查

在客服工作台页面按对应键即可：

| 热键 | 功能 | 使用方式 | 结果 |
|------|------|---------|------|
| **F6** | 下载媒体文件 | 复制图片/视频链接 → 按 F6 | 保存到桌面 `CS_Media` 文件夹 |
| **F7** / **F8** | 提炼工单 | 直接按（**免框选**） | 一句话总结进剪贴板 + 显示在悬浮窗 |
| **F9** | 智能解答 | 直接按（**免框选**；想指定范围也可先选中聊天区域） | AI 生成回复并**自动填入网页回复框** |
| **F10** | 公关润色 | 选中草稿/领导批示 → 按 F10 | 润色为官方话术后替换原内容 |
| **Ctrl + Alt + H** | 召回悬浮窗 | 任何时候直接按 | 悬浮窗回到右下角并重新置顶（**看不见悬浮窗时的救命键**） |
| **Ctrl + Alt + M** | 折叠/展开悬浮窗 | 直接按 | 收成一条细条 / 展开完整面板 |
| **Esc** | 清空小窗"暂存内容" | 任何时候直接按 | 「最近提炼 / 框选预览 / F9·F10 结果」清空 + **无条件清空剪贴板**（防止玩家信息留在剪贴板里） |

> F8 与 F7 完全等价，习惯按哪个都行。
> `Ctrl+Alt+H` / `Ctrl+Alt+M` / `Esc` 走的是全局热键，**不依赖浏览器焦点**，
> 因此即使在别的窗口也能把悬浮窗拉回来 / 清掉暂存内容（`Esc` 不会吞掉按键，页面里的 Esc 照常生效）。

### 5.2 F9 智能解答的 6 种结果

F9 是最常用的功能，它会自动判断工单状态：

| 提示 | 含义 | 你该做什么 |
|------|------|-----------|
| 👋 **【开场】** | 玩家只说"在吗/客服"没描述问题 | 直接发送已填好的开场白 |
| 📸 **【要信息】** | 问题模糊，需要截图/录屏 | 直接发送追问话术 |
| ✅ **官方解答已填入** | 正常业务问题，已给出答案 | **核对后**发送 |
| 🚪 **【超时关单】** | 客服最后发言且超 2 小时 | 可发送并关单 |
| 🚨 **【漏单补救】** | 客服只说了"正在查询"就没下文 | 已补上正解，可直接发送 |
| ⏸️ **等待玩家回复中** | 客服最后发言未满 2 小时 | 不用处理，等玩家回 |

另外两种特殊情况：
- **⚠️ 规章未收录（内部标记，玩家看不到）**：AI 判断表格里没有答案时，会在**给系统看的**第一行标注
  `【规章库未收录，请上报内部群核实】` —— **这行永远不会出现在玩家对话框里**（出站安全闸会整块删掉它）。
  系统对玩家的处理是：
  1. 给玩家发**安抚话术**：`亲爱的玩家，您的问题我已经收到啦，正在为您查询相关信息，请稍等片刻哦~`
  2. **三短一长长报警** + Bark 推送 + 手机黄色横幅
  3. 该会话**置顶**（列表最前 + 📌🙋）
  4. 自动把 **玩家信息 + 问题总结 + 处理建议** 复制到剪贴板，你直接粘去群里/工单备注即可
  （**不会**自动挂起工单、**不会**把任何内部话甩给玩家）
- **❌ AI 未返回内容(接口异常)，已阻止粘贴**：网络/密钥问题，**系统会阻止粘贴**，不会把错误信息发出去

> 💡 **F9 到底把什么发给 AI？** 就是**当前这个工单的聊天记录**（玩家发的内容 + 必要的客服发言）：
> 先看你有没有选中文字 —— 选了就用选中的；没选就**自动读当前会话**（真·免框选）。
> 生成结果优先**直接写进网页回复框**（不依赖光标位置，也不会被剪贴板内容污染）；
> 探针没连上时才退回"复制到剪贴板 + Ctrl+V"。
> **自动回复（非手动按 F9）时**还会按你的节奏走：等 1~3 分钟随机、玩家继续说话就重新计时（见 6.6）。

### 5.5 话术安全闸（玩家永远看不到"内部话"）

**铁律**：发给玩家的任何一句话里，**绝不能出现**下面这些字样 —— 违反会被玩家投诉，也可能被平台判定违规。

| 类别 | 禁词（命中即改写/删除） |
|------|------------------------|
| 内部组织 | `内部群`、`群内客服`、`群里的人工`、`群聊`、`上报`、`报备群` |
| 补偿承诺 | `补偿`、`赔偿`、`补发`（连同紧跟的金额，如"补偿您100钻石"整句换成中性说法） |
| 时间承诺 | `承诺…`、`保证…`、`一定会修复`、`48小时内修复/到账`、`马上/立刻修复` |
| 技术黑话 | `BUG`、`漏洞`、`程序错误`、`F6~F10` 等内部快捷键 |
| 内部提示 | `【规章库未收录…】` 这类内部标记（**整块删除**） |

**闸门装在哪里**（每一处"可能进玩家对话框"的文本都过闸）：

| 出口 | 说明 |
|------|------|
| AFK 自动回复 / 超时关单 | AI 文案 → 清洗后才发送 |
| 半自动草稿（填进回复框） | 同样清洗（草稿也可能被你顺手发出去） |
| 开场语 / 安抚话术 | 来自表格，但同样复核零禁词 |
| F9 / F10 直填（`/api/fill_draft`） | 清洗后才会写进网页回复框；接口会回传 `filtered` 命中项 |
| 手机端「代回复 / 关单」 | 你从草稿复制来的内容也会被清洗（清洗后为空则直接拦截并提示） |

**怎么自查**：
- 中继窗口里出现 `[安全闸] 已清洗发送内容（…）：N -> M 字` 就是它生效了；
- 出现 `[安全闸] ⚠️ 清洗后仍命中禁词：[…]` 说明还有漏网词，把那条发我，我加规则；
- `【规章库未收录…】` 这类内部提示被清空时，系统会**直接转人工**（发安抚话术 + 长报警），不会硬发一句空话给玩家。

> 出厂禁词表在 `agent_core.py` 的 `OUTBOUND_RULES` / `FORBIDDEN_OUTBOUND`，你可以自己加词。
> 回归测试 `python auto_reply_test.py`（第 7 节）+ `python mobile_feature_test.py`（第 8 节）会验证"零禁词"。

### 5.6 品牌与称谓可配置（仓库源码里不写内部词）

仓库是公开的，所以**源码里只有通用词**（`示例公司` / `客服助手` / `本游戏` / `亲爱的玩家` / `IM 系统`）。
你自己真实的公司名、产品名、游戏名、玩家尊称，全部写在**本地 `config.json` 的 `brand` 段**里（该文件不入库）：

```json
"brand": {
  "company":   "你的公司名",
  "product":   "你的产品名",
  "game":      "你的游戏名",
  "im":        "你的 IM 系统名",
  "honorific": "你对玩家的统一尊称"
}
```

生效范围：AI 提示词里的游戏名与称谓、开场语/安抚话术/兜底话术、手机端 H5 标题、自检页标题、AI 关单结束语。
**不配也能跑**（就用上面的通用词），配了就整体替换 —— 改完**重启中继与 HUD** 生效。

同理，**个人补丁库**走两条路（同名文件优先、未被 git 跟踪）：

| 文件 | 用途 | 是否入库 |
|------|------|----------|
| `patch_rules.local.txt` | 你的真实公关铁律 / 内部话术（推荐写这里） | ❌ 不入库（.gitignore） |
| `patch_rules.txt` | 仓库自带的**通用示例**，没写 local 文件时才用它 | ✅ 入库 |

> 想确认仓库里没有内部词：`git grep -nE "内部禁用词1|内部禁用词2"`（把词换成你要查的），或直接看
> `.gitignore` 里列出的"隐私/内部资料"清单 —— 规章库 xlsx、个人补丁库、内部搭建文档都不会上传。

| 🔴 IM 离线 | 电脑端切到离线（手动离线，不触发警报） |

> - 若显示 ⚫ 电脑未连接，点按会提示「电脑端未连接，请先打开客服工作台」

> - **手动离线会被守住**：你手动挂了离线之后，哪怕工作台自己跳回"在线"（很多 IM 在窗口
>   重新获得焦点时会自动上线），探针会立刻把它改回离线，手机端也会跟着回到 🔴 离线。
>   真想在电脑上改回在线，直接点工作台的状态即可（人的点击永远优先）。

#### 6.4.1 状态「改了没生效」怎么办（V7.7 新增自愈与逃生舱）

**含义**：手机端把状态发下去了，但**网页上没切成功**（页面上没有这个选项、下拉没渲染出来、
或者你当时是「管理员看全部会话」的只读视角）。旧版对这种情况**不吭声**，
结果就是"手机显示忙碌、网页其实在线、两边都改不动"。V7.7 起改成**如实显示 + 自动重试**：

| 你会看到 | 系统在做什么 | 你该做什么 |
|----------|--------------|------------|
| 胶囊显示 `🟡 IM 忙碌（网页仍在线）` | 中继记下"网页实际是 在线"，并已**自动重下 3 次**切换指令 | 等它自动生效；不行就点胶囊 → `♻️ 以网页为准` |
| 手机提示 `⚠️ 已重试 3 次切到「忙碌」，但网页仍是「在线」…` | 试了 3 次都没成功，**不再假装成功** | 在电脑上确认（可能页面确实没有该选项 / 当前只读），或点 `♻️ 以网页为准` |
| 状态面板里多了 `🔁 重试同步` / `♻️ 以网页为准` / `🧭 读一下网页的状态选项` | 三个排障按钮 | `🔁` 再切一次；`♻️` 清掉卡住的状态、跟随网页真实现状；`🧭` 让网页把下拉里**真实可选项**回报过来 |

**最省事的一招**：浏览器直接打开 `http://127.0.0.1:8765/api/im_reset`
（= 清掉卡住的手动锁，以电脑网页的真实现状为准）。自检页 `http://127.0.0.1:8765/diag`
的「IM 状态」卡里也有这个链接，并且会直接告诉你**记录 vs 网页实际**是否一致、已重试几次。

#### 6.4.2 排查“到底卡在哪一环”（V7.8 新增：每一环都有据可查）

一次切换要经过 **手机 → 中继 → 电脑网页（探针点下拉）→ 回读** 四步，任何一步都可能坏。
V7.8 起每一步都留下证据，**不用再看隐藏窗口里的日志**：

| 你想知道 | 去哪儿看 | 说明 |
|----------|----------|------|
| 手机发出的指令到中继了吗 | `/diag` →「IM 状态」→ **上次切换请求** | 显示“切到「忙碌」· 手机/小窗手动 · 时间” |
| 中继发给电脑网页了吗 | `/diag` →「IM 状态」→ **最近一次下发** | `连接 N 个 · 成功 M 个`；M=0 说明页面/脚本没连上 |
| 网页脚本收到并处理了吗 | `GET /api/probe_ping`（或 `/diag` 里的「指令自检 🏓」） | 3 秒内回 `PONG` = 指令确实被处理；同时会**自报浏览器里跑的到底是哪一版代码** |
| 网页上到底有哪些状态可选 | `/diag` →「IM 状态」→ **网页下拉实测** | 探针切换失败时会**自动**把下拉里真实可见的选项（tag/类名/文本）回报过来 |
| 点了却报错/没反应 | `/diag` →「IM 状态」→ **上次动作回执** | 例：`❌ CHANGE_STATUS · 未找到可见的状态选项「IM忙碌」；页面候选：…` |

> ⚠️ **手机端页面请刷新一次**（V7.8 起服务端已禁缓存 `no-store`）：旧缓存的 H5 看不到
> 「以网页为准 / 重试同步」这些新按钮，会误以为“跟之前没区别”。

#### 6.4.3 状态胶囊实机修正（V7.9）：Element 下拉是 **hover 触发**

线上实测（`/diag` 的「网页下拉实测」）拿到真实结构后确认了两件事，也是"点了 3 次都找不到选项"的真因：

| 实测 | 结论 |
|------|------|
| 状态胶囊由外到内是 `div.el-dropdown.status-dropdown` → `span.status-trigger.is-im-online.el-tooltip__trigger` → `span.status-label-text` | 旧版按 DOM 顺序取**第一个**（= 最外层包装 div）→ **点不开**。V7.9 改为**由内到外**排序，逐个尝试（内层靠事件冒泡一定能触达真正的处理器） |
| 类名里有 `el-tooltip__trigger`，且"点完没有任何新节点出现" | Element 的 `el-dropdown`/`el-tooltip` 默认是 **hover 触发**：只派发 `click` 永远不会打开菜单。V7.9 补派 `pointerenter/pointerover/mouseenter/mouseover/mousemove` |
| 失败回执现在会说清是 **「下拉没打开」** 还是 **「打开了但选项对不上」**，并回报下拉面板的类名/文本/HTML 片段 | 下次再有问题，一次就能定位，不用来回复现 |

> 🔒 **测试隔离（V7.9，重要）**：此前测试脚本会把动作指令广播到**所有**探针连接，包括你的真实工作台
> （你看到过"需要选择问题分类才能关单"的提示，就是测试的关单指令打到真实页面了）。现在：
> 测试脚本一律用 `?test=1` 连接，中继的 `ext_targets()` 保证**测试客户端发出的指令只发给同样带 `?test=1` 的探针**；
> 状态切换、挂起、发送、AI 关单、AI 起草全部照此隔离（`send_to_player(..., origin=)`）。
> 真实手机端 / 小窗的指令不受影响。**跑测试再也不会点到你的工单。**

#### 6.4.4 出站三道闸 + 一键停发（V7.9，真实事故后加固）

**事故复盘**：探针的「回复 / 草稿 / 回复并关单」永远作用在**页面当前打开的那个工单**上。
测试脚本造的假会话（`F-…`/`AUTO-…`）走自动回复时，指令被广播到了你的真实探针，
于是**问候语被发进了玩家真实工单**（随后被撤回）。现在的防线是三层，任一层都能挡住：

| 闸 | 规则 | 拦住了什么 |
|----|------|------------|
| ① 出站总开关 | `config.json` → **`outbound_enabled`**（默认 true）。设为 false，所有会进玩家对话框的内容一律不发 | 任何"立刻止血"的需求 |
| ② 页面绑定核对 | 发送前核对 **目标会话 gid == 网页当前打开的工单**（探针上报的 `page_gid`），对不上直接拒绝并在手机上说明原因 | **本次事故**（测试 gid ≠ 真实工单 → 拒绝）+ 未来"手滑发错玩家" |
| ③ 出站安全闸 | 原有的 `safe_outbound` 违禁词清洗（公关生命线） | 内部词汇/承诺/补偿类表述 |

- **一键停发**：浏览器打开 `http://127.0.0.1:8765/api/outbound?on=0`（恢复用 `?on=1`）；
  自检页 `/diag` 的「出站安全」卡里有按钮，也能看到 **是否允许发送 / 网页当前工单 / 测试客户端连接数**。
- **清理测试脏数据**：`http://127.0.0.1:8765/api/purge_test_data`
  （只删 `F-数字`/`AUTO-数字`/`T-A..C-数字`/`CLOSEFAIL-数字` 这类测试会话，真实工单号或 `P+hash` 不会被误删）。
- 手机端在**被拦下时会明确告诉你原因**（例如"电脑网页当前打开的是「A」，不是这条会话「B」"），
  而且**不是让你自己去切**：中继会先自动帮你切过去（见 6.4.5），切不过去才拒发。

#### 6.4.5 手机端不再"看不见会话"、也不再要求你手动切会话（V8.0）

**客服原话**：「手机端主页看不见电脑端所有的我的会话」「你叫我在电脑上手动切换？那我怎么在外面回复消息？」
—— 这两条都是 V7.9 页面绑定闸留下的硬伤，V8.0 改成「**中继替你切，而不是拒绝你**」：

| 能力 | 说明 |
|------|------|
| 📋 **手机主页能看到电脑端全部会话** | 探针每 3 秒扫一次网页左侧 `.session-item` 列表（会话名/最后一条/时间/是否当前会话），变化时上报 `CONV_LIST` → 中继存进 `state.conv_list` → 手机主页多出「**电脑网页上的会话（N）**」分区，**你没聊过的会话也在里面**（标「未打开」，当前那个标「🖥 当前」） |
| 🖱 **点一下就切过去** | 手机点「未打开」的会话 → 中继发 `OPEN_CONV` → 探针在网页左侧列表里**点名点击**那一行 → 页面切过去（= 你在电脑上点一样）。已聊过的会话点了直接打开本地聊天 |
| 🤖 **发送前自动切会话** | 手机代发 / AI 自动回复时，如果**网页当前打开的不是目标会话**，中继先发 `OPEN_CONV` 切过去，探针**确认页面真的是它**了再发送 —— 全程不用人碰电脑（`config.json` → `auto_open_conv=false` 可关掉，关掉后回到"拒发+提示"） |
| 🚫 **点不动就立刻说清楚** | 探针切不过去会**如实回报失败**（"已点击「X」，但页面当前还是「Y」"），中继立刻停手并告诉手机原因，**不会干等**、也不会瞎点 |
| 🔁 **旧版探针会点名** | 如果油猴里还是旧脚本（不认识「切会话」），中继会立刻回你："油猴脚本还是旧版（vX）——请打开 `http://127.0.0.1:8765/probe.js` 重新粘贴一次"，**不用猜** |

- **为什么必须有它**：探针的「回复/草稿/回复并关单」永远作用在**页面当前打开的那个工单**上。
  以前为了防"发错玩家"只能拒发（把麻烦丢给客服），现在改成"**先切对，再操作**"——
  防错能力不变，但远程/AI 回复才真正能无人值守。
- **身份识别**：网页会话列表项里**没有工单号**（无 `data-id`），所以手机端/中继按**会话名**匹配
  （同名会话是已知限制，会在会话名对不上时如实报错而不是发错人）。
- **测试隔离（同一事故的延伸）**：`/api/fill_draft?test=1` 只把草稿发给**测试探针**；
  测试上报的会话列表也只进 `state.conv_list_test`（只给 `/diag` 看），**绝不会出现在你的手机主页上**。

#### 6.4.6 列表合成一份 + 点一下就能进会话 + 网页来新会话也会响（V8.0.1）

**客服反馈**：「点击卡片能在电脑切会话了，就是点不进卡片」「"会话"和"电脑网页上的会话"分组的意义在哪？」
「消息通知也有问题，尤其是电脑网页来新会话时」—— 三条都修了：

| 问题 | 原因 | 现在 |
|------|------|------|
| 点不进卡片 | 点「未打开」的会话只是让电脑切过去，手机没打开聊天页（而且那条会话手机还不认识） | 点一下 = ① 让电脑切过去 ② 等探针上报后**手机自动打开聊天页**（不用点第二次）；如实提示"正在让电脑打开「X」…" |
| 两个分组互相重复 | 一边是"中继认识的会话"、一边是"网页列表"，两边显示同一批会话 | **只留一份列表**，以电脑网页列表为准：中继认识的直接是完整卡片（有未读点/置顶/关单中标记），不认识的标「未打开」；不在网页列表里的（旧会话/残留）单独收尾并写明"不在网页列表里" |
| 界面里混着 `NOTOPEN-1790…` 这种假会话 | 旧版给"中继不认识的会话"造了占位卡片（名字=工单号） | 不再造这种卡片：不认识的会话**直接拒发**并告诉你"先在主页点它一下"；`/api/purge_test_data` 也会清理历史遗留 |
| **网页来新会话不响** | 探针只在**当前打开的工单**里读聊天区 —— 别的会话来了消息（还没点开）根本没有 `PLAYER_MESSAGE`，那条通知链路注定漏 | 探针上报的**会话列表变化**也算事件源：列表里冒出**新会话**或某行**内容变了** → 立刻按"新消息"叮咚 + 顶部提示 + 震动（带会话名与预览），列表里对应行显示未读点（`fresh`）；已被打开的那条不再标记 |
| 手机显示"其实没发出去"的消息 | 旧版先把消息记进会话再尝试发送 | 改成**发送成功才记进去**（拒发就只提示原因，不假装已发） |

- 相关开关/接口都没变：`auto_open_conv`（自动切会话）、`outbound_enabled`（一键停发）、`/api/purge_test_data`（清测试脏数据）。
- 测试隔离延伸到通知：**测试脚本造的列表/消息只推给测试连接**，不会弹到你的真机上；Bark 同样只在真实来源时推。

#### 6.4.7 「半自动绝不自动发消息」+ 翻旧会话不再误响（V8.1，这次是严重问题）

**客服反馈**：「你还是能自动给真实玩家发消息！拦截也不管用」「好像还把我自己编辑的消息拦截了，我要再发一遍才能发出去，然后对话框就会出现两条我同样的消息」「电脑切换到其他旧的会话时，手机不要弹消息提示」。

**① 自动发消息的真凶：开场语（和"安抚话术"）**
旧逻辑只要「会话里有玩家消息 && 没发过开场语」就直接 `SEND_REPLY` —— 而且**半自动也算在内**，
于是：中继重启后你点开任意一条**旧工单**（`greeted` 标记随重启丢了）→ 系统真的给玩家发了一条开场语。
现在的铁律（代码级硬闸，不是口头保证）：

| 层 | 规则 |
|----|------|
| 🔒 **硬闸** | `send_to_player(auto=True)` 的"发送类"指令（`SEND_REPLY`/`ACTION_REPLY_CLOSE`）**只有 AFK 模式允许执行**；半自动/手动模式下自动发送一律拦下（`FILL_DRAFT` 起草不受限） |
| 🎯 **开场语收紧** | 只对「中继**第一次**看到这条会话 + 玩家消息在 3 分钟内 + 还没有客服发过言」的会话处理；半自动只**起草**到输入框（并提示手机"等你确认发送"），AFK 才发送；且带**页面绑定**（不会打到别的工单里） |
| 📢 **安抚话术同样** | 「表格没答案 → 发安抚话术」在半自动下也改成**起草**（原来无条件直接发给玩家） |
| 🧾 **出站审计** | 每次出站都留痕（谁触发/什么模式/发给几个探针/成不成/文本片段），`/diag` 与 `/api/diag` 的 `outbound_log` 可查 —— 出问题不用再猜 |

**② 「对话框出现两条我同样的消息」**
三条防线：`FILL_DRAFT` 默认**绝不覆盖**你输入框里正在写的字（V8.1 探针，除非显式 `overwrite`）；
同一条会话同一段文本 6 秒内重复指令**只发一次**；多个工作台标签页连接时，**只让"当前真的打开着这条会话"的那个探针执行**
（`/api/diag` 的 `warn` 会提示"多开标签页会导致重复发送"）。

**③ 「切换到旧会话时手机不要弹提示」**
`PLAYER_MESSAGE` 的提示收紧为「**中继本来就认识这条会话** + 玩家消息时间戳真的往后走」；
新会话/新消息统一由**会话列表变化**那条链路提示（首次拿到列表只建基线）。
翻旧工单、重启后重看老会话 → 不再叮咚。

**④ 手机页面自带版本号**
顶栏多了一个 `页面 v8.1` 胶囊 —— 以后"改了没生效"第一眼就能分辨（和探针版本胶囊一个思路）。

#### 6.4.8 翻旧工单不再打扰 + 点卡片进会话的加固（V8.2）

| 客服反馈 | 真因 | 现在 |
|----------|------|------|
| 「电脑网页选择**旧对话**，手机还是会收到 **Bark 服务消息**」 | ① 旧会话一被打开，AI 的延迟任务照样会对**几百年前的消息**动手，查不到答案就推一条「🙋 需要人工介入」Bark；② 探针/中继把"第一次看到的历史消息"当成**刚刚**发生（时间戳补成 now） | ① AI 只对**新鲜消息**（默认 10 分钟窗口，`auto_active_window_sec` 可调）动手，旧工单**不插手**；安抚/告警只在消息新鲜时推 Bark，否则只做站内告警；② 消息时间戳优先沿用已知值/探针给的值 —— 翻旧工单不再被误判成新消息（既不响也不推 Bark） |
| 「更新了，但还是进不了卡片的会话」 | `pushChat()` 里 **先渲染、后切视图**：渲染里任何一处抛异常，`showChat()` 就永远不执行 → 表现就是"点了没反应/进不去"（渲染还没做兜底） | **先切视图**再渲染；每一步各自 `try/catch`；列表点击再加一层**兜底委托**（某次没绑上也能进会话，`_h5Handled` 防重复处理）；会话数据还没到会明确提示而不是静默 |
| 「手机端『其他会话』感觉很鸡肋」 | 不在网页列表里的历史会话被一股脑列出来 | 默认**收起成一行**「其它会话（不在网页列表里）N 条 · 点开」；只有**需要留意**的（未读/🙋需人工/⏳关单中）才直接列出来；没有网页列表时（旧探针）照旧全列 |

> 排查提示：手机顶栏现在有 **`页面 vX`** 胶囊。以后遇到"改了没生效"，先看这个数字对不对 —— 对不上就是手机端缓存/没刷新；对得上再往下查。

#### 6.4.9 会话里的按键改成"真正的按钮"+"AI 立刻起草"点了就执行（V8.4）

**客服反馈**：「里面的所有快捷按键比如『AI回复并关单』都是开关，我要它们是按钮」「AI 起草点击后立刻起草，而不是等待 1~3 分钟」。

| 改动 | 说明 |
|------|------|
| 🔘 **视觉：按钮就是按钮** | 会话顶部那一排改成**实心方块按钮**（38px 高 / 11px 圆角 / 加粗文字），不再用胶囊样式；「🤖 AI 回复并关单」用**主按钮高亮**（青蓝渐变） |
| 🔒 **"关闭"不再用变灰表达** | 以前功能关闭时把按钮 `opacity` 调暗（看着像开关被关掉）。现在改成 **🔒 + 说明文字**（如 `🤖 AI 回复并关单 🔒`），下方提示行写清原因 |
| ⚡ **「✨ AI 立刻起草」= 点一下立刻起草** | 走 `force=True`：**不进 1~3 分钟的延迟队列**（那 1~3 分钟只用于"新消息后的自动起草"）。手动/半自动模式下点它同样会立刻起草 |

#### 6.4.10 复查补丁（V8.5）：测试绝不许打扰客服本人 + 手机草稿不冲掉你写的字

| 现象 | 真因 | 现在 |

#### 6.4.11 复查补丁（V8.5.1）：切旧会话不再误响 + 测试不再碰 IM 状态

这一轮又抓到 3 个问题，全部修掉：

| 「电脑切到**旧会话**，手机还是响铃 / 收到 Bark」 | 「我正在看这条会话」用的是 `_LAST_PAGE_GID`，而切会话时探针会**先报会话列表**（active 行变了）把它提前改成新会话 → 把"翻旧会话的历史"误判成新消息 | 改用 `_LAST_MSG_GID`（**只**由 PLAYER_MESSAGE 更新）判断，与列表的 page_gid 解耦 —— 翻旧会话不再误响 |
| 「**测试又把我 IM 状态改成在线了**」 | 测试客户端（`?test=1`）的 `SET_IM_STATUS` / `SET_MODE` / `RESET_IM_STATE` / 探针上报 `IM_STATUS` 等，都直接写真实 `im_state.json` / `mode_state.json` | 测试来源一律**只改内存、不落盘**（`persist=False`）；真实切换照常落盘。单测也加了"结束恢复现场"，不再污染状态文件 |

> 然后看顶栏是不是 `页面 v8.5.1` —— 不是就说明还是旧缓存；是的话再往下查（探针是否连上、会话数据是否到位）。


#### 6.4.12 实机根因（V8.4）：手机端「所有会话都进不去」= 玩家名解析错，与会话列表对不上

**客服反馈**：「电脑点旧会话手机还是收到消息」「手机点旧会话电脑自动切换也会通知」「手机会话详情进不去」「会话详情的按键没做好」，且强调「全是最新版」。

**真因（一条链）**：本工作台是 `/imChat/workstation`，右侧面板的文本开头多了一排**页签**：

```
玩家信息 | 服务记录 | 数据查询Agent | AI 智能总结 | 收起 | 暂无总结数据 | 基本信息 | UID: | 100000432614 | 角色名: | 羽婵 | ...
```

- 探针解析玩家名时，**页签名「服务记录」被当成了玩家名**（真名是「羽婵」）；
- 而且 `UID:` / `角色名:` 的值在**下一段**（换行被转成 `" | "`），旧正则只认 `字段名: 值` → 一个也读不出来，于是退化成"取第一个像名字的段"→ 抓到页签名。
- 结果：中继认识的会话名是**「服务记录」**，而网页会话列表里的真名是**「羽婵」** → **两边对不上**：
  - 手机端把**每一条**会话都渲染成「未打开」（点了只会让电脑切，切完还是匹配不上 → **进不去详情**；进不去 → `activeGroupId` 为空 → 详情页按钮点了没反应）；
  - 新会话/新消息的通知按**名字**匹配 → **全部失效**（新会话不提示，点旧会话反而触发）。

**修复（`probe.js`，只加护栏不动靶点）**：
1. 面板解析支持实机格式 **`字段名: | 值`**（`UID: | 100000432614`、`角色名: | 羽婵`）；
2. **页签名黑名单**（服务记录 / 数据查询Agent / AI 智能总结 / 收起…）绝不当作玩家名；
3. **玩家名以「网页会话列表高亮行」为准**（`.session-item.active .session-name`）—— 与手机端列表、切会话用的名字**同源**，从根上保证两边一致。

**验证**：`probe_smoke_test.js` 131 → **134 通过 / 0 失败**（新增 3 项：实机格式能解析出「羽婵」、页签名绝不入名、名字与列表同源）。

> ⚠️ **必须更新油猴脚本**：探针代码跑在浏览器里，改了源文件也要重新粘贴。
> 打开 `http://127.0.0.1:8765/probe.js` → 全选复制 → Tampermonkey 覆盖粘贴 → Ctrl+S → 刷新工作台。
> 判断是否更新成功：`/diag` 里探针版本显示 **v8.4**（不是 8.2/8.3），且手机端会话名变成**真实玩家名**。

### 6.5 回复模式三档（顶部第二个下拉）

点顶部**第二个下拉**（默认显示「半自动」）会弹出底部面板，三档任选：

| 模式 | 行为 | 什么时候用 |
|------|------|-----------|
| ✋ **手动** | **只提醒新消息，AI 不自动起草** | 想完全自己写时（把"AI 自动起草"关掉） |
| 🤖 **半自动**（默认） | AI 自动起草推到回复框，**等你确认发送** | 日常 |
| 🚀 **AFK 全自动** | AI **直接发送**给玩家，人完全不参与 | 短期离开工位 |

AFK 模式下：

- 正常问题 → 直接回复玩家
- 超时工单 → 直接回复并关单
- **规章未收录** → 自动挂起 + 推 Bark 提醒你介入

> ⚠️ 建议只在短期离开工位时开启 AFK；切回「手动 / 半自动」即刻生效（面板上有 ✓ 标出当前档位）。

> **电脑小窗也能切**：悬浮窗标题栏的 `🤖半自动 / 🚀AFK / ✋手动` 按钮（点一下循环，见 5.3）。
> **两边冲突时以手机端为准**：手机端改过之后的 10 分钟内（`mobile_mode_priority_sec` 可调），
> 小窗的切换会被拒绝并提示；小窗每 5 秒跟随中继显示，所以手机端一改，小窗立刻跟着变。
> **默认永远是半自动**：AI 只把草稿填进输入框，**不发送**。

### 6.6 自动回复节奏（V7.4 新增：不秒回、等人说完）

> 客服反馈："玩家一发就秒回，像脚本、又费 token、还打断玩家说话。"

| 环节 | 现在的行为 |
|------|-----------|
| 玩家**第一次**发言 | **立刻发一条开场语**，严格取自表格（话术库「没有描述问题/直接转人工」那一类）；表格缺了才用兜底句 |
| 之后 | **不秒回**：等 **1~3 分钟随机**（`auto_reply_delay_min_sec` / `max` 可调）；期间玩家再来消息就**重新计时**，确认他不说了才回复 |
| 该不该回 | 只有"**玩家最后发言**且这条还没被回过"才回 —— 客服最后发言时绝不抢话 |
| 发给 AI 的记录 | 程序自行判断：**丢掉玩家开口之前的客服发言**；玩家之后的客服发言只保留最近 2 条（省 token） |
| AI 判为「规章库没收录」 | 先给玩家发这句安抚：`亲爱的玩家，您的问题我已经收到啦，正在为您查询相关信息，请稍等片刻哦~`，然后**长报警** + **该会话置顶** + **自动把玩家信息和问题总结复制到剪贴板**（**不会**自动挂起工单） |
| 手动 / 半自动 / AFK | ✋手动 = 只提醒不起草；🤖半自动 = AI 起草到回复框；🚀AFK = 直接回复。三档都能享受上面的节奏控制 |

**手机上主动点「✨ AI 起草」不受延迟限制**（你点的就是立刻要），但也受"手动模式"约束。

> 💡 想临时改成"立刻回"：手机端可调 `SET_AUTO_DELAY`（例如 0~0），或把 `config.json` 里
> `auto_reply_delay_min_sec` / `auto_reply_delay_max_sec` 都设成 0。

### 6.7 三种提示音怎么区分

| 声音 | 场合 | 特征 |
|------|------|------|
| 叮~咚~（桌上"叮咚"/**手机双音**） | **玩家发来新消息** | 两个短促正弦音，清脆；**手机同时弹「💬 玩家名：预览」并轻震动** |
| 连续警笛（锯齿波，会一直响） | **IM 异常掉线**（VPN/网络断） | 1000ms 一次持续循环 + 手机全屏红层 |
| **三短一长**（手机三声方波；电脑 700Hz×3 + 500Hz 长音） | **需要人工介入**（表格里没有答案，已发安抚话术） | 只响一轮，同时自动复制玩家信息+问题总结 |

> 手机端响铃的触发条件是"**末尾多了玩家新消息**"（中继即时推 `NEW_MESSAGE`）：
> 半自动 / AFK / 手动三种模式都会响；同一条消息重复上报不会连环响；
> **你正在看的那个会话不响**（消息已经显示在聊天流里，避免自己打扰自己）。
> 如果手机没响：① 确认不是"正在看该会话"；② 确认手机页面在前台且不是静音；
> ③ iOS 需要**先点过页面任意位置**（浏览器要求一次交互才允许出声）；
> ④ 锁屏想收到 → 开 `config.json` 的 `"bark_on_new_message": true`（会额外推 Bark）。

## 七、规章库自动更新

线上规章一改，**AI 答复必须跟着变**。系统提供三种更新方式，**都不需要表格 API 权限**。

### 7.1 方式一：监听目录（推荐）

**一次性配置**：在 `config.json` 里指定你导出 Excel 的目录

```json
"rules_watch_dir": "C:\\Users\\你的用户名\\Documents\\表格导出",
"rules_sync_interval_minutes": 30
```

**以后每次更新只需两步**：

1. 在线表格 → 导出为 Excel
2. 把文件丢进那个目录

系统每 30 分钟检查一次，发现有更新会自动：
覆盖 → 备份旧文件 → **热重载知识库** → 发 Bark 通知

**全程不用重启服务。**

### 7.2 方式二：手动覆盖（最简单）

直接把新的 `rules.xlsx` 拖到项目根目录覆盖旧的即可。

系统会在**下次处理工单时自动识别并重载**（按文件修改时间判断），同样不用重启。

### 7.3 方式三：直链拉取

如果你们有能直接返回 Excel 的下载链接：

```json
"rules_sync_url": "https://你们的地址/export.xlsx"
```

系统会定时下载 → 校验 → 备份 → 替换（坏文件会被拒绝，不会污染知识库）。

### 7.4 后台常驻同步（可选）

不想让中继服务管这件事，可以单独挂一个：

```bash
python rules_sync.py --watch        # 常驻，前台可见
python rules_sync.py --once         # 只跑一次（适合挂 Windows 任务计划）
```

挂任务计划：`任务计划程序 → 创建基本任务 → 每天 → 操作填 python rules_sync.py --once`

### 7.5 检查同步状态

```bash
python rules_sync.py --info -v
```

或看中继服务的黑框窗口，更新时会出现：

```
[规章库] 从监听目录更新: 已更新
[规章库] 已重载：常驻 11482 字符 / 检索池 713 条 / 共 843 条 / 13 张表
```

### 7.6 关于知识库如何进入 AI

系统不会把 800 多条规则全塞给 AI（那会超长且昂贵），而是：

| 类型 | 处理方式 |
|------|---------|
| **小表**（关单优先级、账号、已知BUG 等） | **常驻**每次请求 |
| **大表**（631 条 FAQ 等） | 按当前工单内容**检索最相关的 25 条**再送入 |

所以无论工单问什么，相关规则都能命中，且 token 占用稳定。

### 7.7 回滚

每次覆盖前会备份旧文件：

```
rules.xlsx          ← 当前
rules.xlsx.bak      ← 上一版
```

出问题就把 `.bak` 改名回去即可。

### 7.8 从人工回复里"逆向蒸馏"话术规则（V8.3，离线工具）

**痛点**：AI 只会照规章库答，学不到你自己的**口吻与分寸** —— 什么话能说、什么话要绕着说、
什么时候该索要凭证、玩家不配合时怎么推进。这些靠手写提示词很难描述清楚。

**做法**：让探针把**客服真人发出的回复**（连同当时的工单上下文）静默记下来，
再由一个**离线脚本**把这些真实样本喂给大模型，逆向蒸馏成"固定句式 / 避坑策略 / 索要信息边界 / 3 组 Few-Shot"，
产出一份**人可读、可直接并入补丁库**的规则补丁。

三步链路：

| 步骤 | 谁在做 | 做什么 | 产物 |
|------|--------|--------|------|
| ① 静默录制 | `probe.js`（油猴，V8.3） | 你**真人**点「回复」或按回车发送时，抓下"输入框原文 + 玩家信息 + 当前对话"，回传 `RECORD_MANUAL_DEMO` | 事件包（不落盘） |
| ② 落盘 | `bridge_server.py` | 追加写入 JSONL（单行一条；极简防刷：正文 <2 字忽略、同工单同文本 6 秒内只记一次） | `demonstrations.jsonl` |
| ③ 蒸馏 | `distill_rules.py`（**手动跑**） | 取最近 15~30 条样本 → 调 DeepSeek 当"规则逆向工程师" → 写结果 | `distilled_patch.txt` |

**四条硬保证**（代码级，不是口头承诺）：

| 保证 | 说明 |
|------|------|
| 🤫 完全静默、不影响操作 | 监听只在 `mousedown`/`keydown` 的**捕获阶段**读一下输入框：不 `preventDefault`、不改输入框、不点按钮、不代发；任何异常只打 `console.warn` |
| 🧍 只记"真人" | AI 草稿 / 手机代发走的是脚本合成的点击事件（`isTrusted=false`），**一律跳过** —— 否则会把系统自己生成的话当成"人工标准答案"喂给模型 |
| ✅ 记的都是"真发出去的" | 发送 1.2 秒后回查：输入框真的清空了 **或** 对话里真的出现了这句话，才算数（点了没发出去的误触不记） |
| 🛡 零出站 | 这条链路**只落盘、不发送**：不填草稿、不发给玩家，因此不经过（也不需要经过）出站安全闸；**蒸馏出的话术将来生成回复时仍然过闸** |

**怎么确认它真的在记**（三层证据，任选其一）：

```bash
# ① 中继窗口：每记到一条就打印一行
[DemoRecorder] 成功捕获 1 条人工标准回复样本

# ② 自检页 http://127.0.0.1:8765/diag ->「工单与知识库」卡片里的一行
人工样本（蒸馏语料）：12 条 · 见 demonstrations.jsonl
#    或直接读 JSON：http://127.0.0.1:8765/api/diag 里的 demo_records

# ③ 工作台页面 Console（探针侧）
__probe.demos()     # 打印 captureEnabled / captured / sent / skipped / lastReply
```

**怎么用**（在项目目录打开 PowerShell）：

```bash
# 0) 先攒样本：让客服照常回复一段时间（建议 15~30 条，条数看 /diag 的「人工样本」）

# 1) 只看会喂给模型的提示词（不调用接口、不花一分钱）
python distill_rules.py --dry-run

# 2) 真正蒸馏：结果写进 distilled_patch.txt，同时打到控制台方便当场看
python distill_rules.py --limit 20 --show
#    可选参数：--limit 15~30（太少没规律、太多烧 token，脚本会夹在 5~60）
#              --file demonstrations.test.jsonl（测试语料是单独一份，别混进真实语料）
#              --model 换成你想用的模型名

# 3) 人工看过、确认没问题后，再并入补丁库（AI 下次请求就会带上它）
python distill_rules.py --append                  # 默认追加到 patch_rules.local.txt
python distill_rules.py --append patch_rules.txt  # 也可写进仓库自带示例（不推荐：那只是通用示例）
```

**产物长什么样**：`distilled_patch.txt` = 一段自动生成的头（时间/样本数/模型/禁词体检提示）+ 下面五个小节：

```
【固定句式库】          按场景分组、带 {占位符} 的模板，可直接套用
【避坑策略】            "不要说什么 → 换成什么"，每条都注明依据是第几条样本
【索要信息边界】        什么情况必须先要什么、什么情况不该再要、玩家不给时怎么推进
【Few-Shot 范例（3 组）】 最精炼的 3 组"玩家：… / 客服：…"
【样本观察备注】        这批样本的共同风格 + 还没覆盖、建议补录的场景
```

**注意事项**：

- 样本文件**含玩家昵称/UID 等真实工单内容**，已在 `.gitignore` 里排除，**不会上传 Git**；
  但请像对待规章库表格一样自己留意清理与备份（见 13.1）。
- 蒸馏结果里若出现承诺/补偿这类**不能对玩家说**的字眼，脚本会做一次**只提示、不改写**的禁词体检并写进文件头部 ——
  这些字眼出现在给玩家的话术里会被出站安全闸改写，请人工审阅时先改成中性说法。
- 测试来源（`?test=1` 的假探针）产生的样本单独进 `demonstrations.test.jsonl`，**不会污染真实语料**（沿用测试隔离铁律）。
- 临时关掉录制：工作台 Console 执行 `__probe.config.demoCapture = false`（当次有效，刷新即恢复）。

## 八、AI 一键回复并关单

### 8.1 什么时候用

玩家问题已经解答完、不需要再等待时 —— 一条命令完成「选分类 + 写结束语 + 回复 + 关单」。

### 8.2 操作步骤

1. 手机进入该玩家聊天页
2. 点 **🤖 AI回复并关单**
3. 弹窗确认 → 点「确定」
4. 底部提示 `AI 正在生成结束语…`
5. 完成后提示 `已回复并关单 · 分类：xxx`
6. **该会话自动从列表消失**

### 8.3 它到底做了什么

```
你点按钮
   ↓
后端把工单聊天记录交给 AI
   ↓
AI 同时产出两样东西：
   ① 问题分类（从页面真实分类里选，如「充值问题」）
   ② 给玩家的结束语（已过滤敏感词、统一称谓）
   ↓
下发给电脑端探针执行：
   填入结束语 → 选中对应问题分类 → 点击「回复并关单」
   ↓
从手机列表移除该会话 + 推送 Bark 留痕
```

### 8.4 分类是怎么确定的（重要）

系统**不会凭空编造分类**，按优先级取：

| 顺序 | 来源 |
|------|------|
| 1 | 探针从网页**级联选择器**读到的真实分类（只读，不会误点） |
| 2 | `config.json` 里你手工配置的 `close_category_options` |
| 3 | 兜底用 `close_category_default`（默认「其他」） |

**查看探针抓到了哪些分类**（浏览器打开）：

```
http://192.168.x.x:8765/api/categories
```

若返回 `options` 为空，说明探针没读到分类选择器 —— 请先在电脑上打开一个工单（
让页面渲染出「问题分类」下拉框），然后重新访问。

若 AI 选的分类和你们的不一致，把正确分类名填进配置：

```json
"close_category_options": ["登录问题", "充值未到账", "游戏异常", "画面卡顿", "其他"]
```

同时确认分类层级路径与页面一致：

```json
"close_category_path": ["一级分类的实际名称", "二级分类的实际名称"]
```

### 8.5 安全保证

| 情况 | 结果 |
|------|------|
| AI 接口异常 / 无返回 | ❌ 提示失败，**会话不会被删除** |
| 电脑端探针掉线 | ❌ 提示「电脑端探针未连接，无法关单」，**不删会话** |
| 分类没匹配到 | 宁可不选 + 如实回报候选（绝不盲选错分类） |
| **页面没点到「回复并关单」** | ⏳/❌ 提示具体原因（含页面按钮清单），**会话保留**，可手动补 |

> 所有关单动作都会推一条 Bark 通知，留痕可查。

### 8.6 「回复并关单」到底做了什么（V7.5 完整链路）

手机端点 **🤖 AI 回复并关单** 之后，系统按下面 6 步走（任何一步失败都会保留会话、并告诉你原因）：

| 步骤 | 谁在做 | 具体动作 |
|------|--------|----------|
| 1 | 手机端 | 二次确认 → 发 `AI_CLOSE`（带工单号）给中继 |
| 2 | 中继 | 取该会话的完整聊天记录 + 页面上的真实问题分类（`category_options`，没有就用配置兜底） |
| 3 | 中继 → AI | 调 DeepSeek 生成 `{"category": "问题分类", "content": "给玩家的结束语"}`；分类必须落在页面真实候选里，否则落到「其他」 |
| 4 | 中继 | **安全闸**清洗结束语（内部群/补偿/承诺/BUG 等一律改写或删除）；清洗后为空 → 直接取消关单 |
| 5 | 中继 → 探针 | 下发 `ACTION_REPLY_CLOSE`（含结束语、分类、分类路径、兜底分类、工单号）；中继把会话标记为 **⏳ 关单中**（**先不移除**），并起一个 20 秒超时看门狗 |
| 6 | 探针（页面） | 填入回复框 →（按配置留 2.2s）选问题分类 → 点「回复并关单」→ 回报 `ACTION_RESULT`（带工单号） |
| 7 | 中继 | 收到 **成功**回执 → 才把会话从列表移除 + Bark 通知「已回复并关单」<br>收到**失败**回执 → 会话保留，手机端常驻显示失败原因（含页面真实按钮名）<br>20 秒没回执 → 会话保留 + 提示「页面未回报结果」 |

**为什么这么做**（V7.5 的关键修复）：旧实现是"AI 一生成完就把卡片删掉"，
如果页面其实没点到「回复并关单」，就会变成**卡片没了、工单还挂着**，客服以为已关单。
现在改成**探针确认成功才移除**，宁可不删也不误删。

> 想手动兜底：手机输入框里写好结束语 → 点 **✅ 关单**（走同一条确认链路），
> 或者直接在电脑上点页面的「回复并关单」。

## 九、异常掉线警报

### 9.1 会发生什么

当探针检测到工作台显示 **IM离线**（VPN 掉线 / 网络断开）时：

| 位置 | 表现 |
|------|------|
| 电脑端 | **持续警报音** + 悬浮窗状态变红 |
| 手机端 | **全屏红色浮层** + 手机也响警报音 |
| 手机通知 | 收到 Bark「🚨 异常掉线警报」 |

### 9.2 怎么消除

任选一种：

| 方式 | 操作 |
|------|------|
| 手机静音 | 红色浮层上点 **「点击静音并忽略」** |
| 手机恢复 | 顶部状态按钮 → 切到 **🟢 IM 在线**（自动清警报） |
| 电脑恢复 | 手动把工作台切回「IM在线」（探针自动检测并解除） |

### 9.3 为什么不会重复轰炸

- 探针只在**状态发生变化**时上报一次（不会每 2 秒重发）
- 后端处理后会回执确认，探针停止重复上报

### 9.4 手动离线不报警（并且会被守住）

你自己在工作台点「IM离线」（下班）**不会**触发警报 ——
探针能区分「手动离线」与「异常掉线」。

而且从 v7.4 起，**手动离线会被守住**：工作台自己跳回「IM在线」（很多 IM 在你切窗口、
页面重新获得焦点时会自动上线）时，探针会立刻把它改回「IM离线」，手机端也始终显示 🔴 离线；
中继服务重启也不会把状态变成在线。日志里能看到：

```
🛡️ [探针] 检测到网页把状态自动改成了「IM在线」，按你的手动离线设置改回「IM离线」（第 1 次）
```

> 你自己点「IM在线 / IM忙碌」永远优先（1.5 秒内不会被扳回）。
> 若确实不想被守护（想让手机端完全跟随网页），把 `config.json` 的 `keep_manual_offline` 设为 `false`。

## 十一、接口与协议

> 用于排障和二次开发，日常使用不需要看这一节。

### 11.1 HTTP 接口

| 地址 | 用途 |
|------|------|
| `http://IP:8765/` | 手机端网页 |
| `http://IP:8765/diag` | **系统自检页**（中继 / 探针 / 手机端 / 知识库一屏看懂，每 5 秒自动刷新） |
| `http://IP:8765/api/diag` | 同上的 JSON 版（供脚本/悬浮窗读取） |
| `http://IP:8765/probe.js` | **最新探针脚本全文**（用来核对油猴里那版是否最新）；加 `?download=1` 直接下载 |
| `http://IP:8765/api/ticket` | 当前工单数据（F7 提炼用） |
| `http://IP:8765/api/categories` | 已抓取的问题分类 + 分类配置 |
| `POST http://IP:8765/api/fill_draft` | 把文案直接写进网页回复框（F9/F10 免框选走这里，body: `{"content":"…"}`） |
| `http://IP:8765/api/alerts` | 需要人工介入的告警队列（桌面 HUD / 脚本读取） |
| `POST http://IP:8765/api/alerts/ack` | 确认告警（body: `{"ids":[…]}`；不传 ids = 清空） |
| `POST http://IP:8765/api/mode` | 电脑小窗切回复模式（body: `{"mode":"manual|semi|afk","source":"desktop"}`；手机端优先时返回 `ok:false`） |

在电脑浏览器打开这些地址，可快速确认服务是否正常。
**排障时第一个该打开的永远是 `/diag`**（或 `/api/diag`），它能直接告诉你"谁没在线"。

`/api/diag` 里几个关键字段：

| 字段 | 含义 |
|------|------|
| `probe.online` | 油猴脚本是否连上（`false` = 脚本没跑起来） |
| `probe.version` / `probe.version_reported` | 脚本版本；**连上了但 version 为空 = 油猴里是旧脚本** |
| `probe.page` | 探针当前所在页面（可识破"开错页面/多开"） |
| `probe.last_seen_sec` | 最近一次心跳距今多少秒 |
| `mobile.online_clients` | 手机端在线连接数 |
| `im.status` / `im.status_text` | 手机端顶部下拉框当前显示的 IM 状态（1在线/2忙碌/3离线） |
| `im.known` | **是否已从电脑网页核实**（`false` 时手机端显示「正在获取…」，不会假装在线） |
| `im.manual` | 该状态是否来自客服手动选择（配合离线守护） |

### 12.2 手机显示「暂无会话」/ 怀疑脚本没生效

**第一步：打开自检页 `http://127.0.0.1:8765/diag`**（电脑浏览器，会每 5 秒自动刷新）。

| 自检页显示 | 说明 | 处理 |
|-----------|------|------|
| 探针 🔴 未连接 | 油猴脚本没跑起来 | 见下面第 2 步 |
| 探针 🟡 已连接 · 未上报版本（旧脚本） | 脚本是旧版（< v8.0），新功能都没有 | 按 12.3 更新脚本 |
| 探针 🟢 已连接 · v7.5，但会话数 0 | 脚本正常，只是**没打开工单** | 在工作台里点开一个工单 |
| 中继 🔴 | 服务没跑 | 重启 `bridge_server.py` |

**第二步：确认脚本是否加载**（工作台页面按 `F12` 打开控制台）：

```
🚀 [工单探针 V7.3] 真实靶点定位系统与防暴雷机制已就绪！
✅ [探针] WebSocket 连接成功
```

更直观的办法：**看页面左下角有没有绿色小胶囊** `🟢 探针 v8.0 · 已连接`

| 看到什么 | 结论 |
|---------|------|
| 🟢 胶囊 | 一切正常 ✅ |
| 🟡/🔴 胶囊 | 脚本生效了，但没连上中继 → 确认 `bridge_server.py` 在跑，然后**单击胶囊立即重连** |
| 完全没有胶囊 | 脚本没生效 → Tampermonkey 里没启用 / 没保存 / 页面没刷新 |
| 控制台报 `SyntaxError: Missing catch or finally after try` | **油猴里是残缺的旧脚本**（复制粘贴被截断）→ 按 12.3 整段重新覆盖 |

**第三步：确认中继服务**

```
http://127.0.0.1:8765/diag      # 能看到自检页 = 服务正常
```

**第四步：确认已打开工单** —— 探针只在「IM 工作台 + 已打开具体工单」时抓取消息。

> 控制台里随时可以自查：输入 `__probe.status()` 回车，
> 会打印版本、连接状态、胶囊状态；`__probe.reconnect()` 可手动重连。

### 12.3 手机只有一个玩家 / 旧会话被顶掉 / 要用最新脚本

**这是旧版探针的已知问题**（旧版把所有工单都写成同一个 ID）。

**解决：更新油猴脚本**

1. 浏览器打开 `http://127.0.0.1:8765/probe.js`（这就是项目里最新的脚本全文）
2. 全选复制（`Ctrl+A` → `Ctrl+C`）
3. Tampermonkey → 你的探针脚本 → **全选删除** → 粘贴
4. `Ctrl+S` 保存 → **刷新工作台页面**

**怎么确认更新成功**：页面左下角出现 `🟢 探针 v8.0 · 已连接`，
并且 `http://127.0.0.1:8765/diag` 的探针版本变成 `v7.5`（不再显示"未上报版本"）。

验证多工单隔离：打开两个不同玩家的工单，手机主页应能看到**两个独立会话**。

> ⚠️ 只把新版内容**追加**到旧脚本后面是**不行**的（会出现两个探针抢同一连接）。
> 必须先全选删除再粘贴。

### 12.4 AI 不回复 / 提示「接口异常」

| 检查项 | 方法 |
|--------|------|
| API Key 是否正确 | `config.json` 的 `deepseek_api_key` 是否 `sk-` 开头且无空格 |
| 账户是否有余额 | 登录 DeepSeek 开放平台查看 |
| 网络是否通 | 浏览器打开 `https://api.deepseek.com` |
| 是否被 VPN 干扰 | 尝试关闭 VPN 或换网络 |

> **重要**：AI 失败时系统**不会**把错误信息发出去 ——
> F9 会提示「❌ AI 未返回内容（接口异常），已阻止粘贴」，这是**保护机制**，不是 bug。

### 12.6 关单后分类不对

1. 浏览器打开 `http://127.0.0.1:8765/api/categories`
2. 看 `options` 里的一级分类**是否与你们页面一致**
3. 不一致或为空 → 在 `config.json` 手工指定：
   ```json
   "close_category_options": ["登录问题", "充值未到账", "游戏异常", "其他"]
   ```
4. 同时把真实的层级名称填进：
   ```json
   "close_category_path": ["实际一级分类名", "实际二级分类名"]
   ```

### 12.9 手机界面卡在几分钟前的状态

### 12.10 手机顶部下拉框点不动 / 状态不对

**第一步：先看下拉框上写的是什么**

| 下拉框显示 | 说明 | 处理 |
|---------|------|------|
| ⚫ **电脑未连接** | 电脑端网页没开着 / 探针掉线 | 打开电脑上的客服工作台页面即可（此时点按会提示原因，不是"坏了"） |
| ⏳ **正在获取…** | 刚打开手机页，正在问电脑网页要真实状态 | 等 1 秒；若一直不变 → 电脑端网页/探针没在线（见 12.1） |
| 🟢/🟡/🔴 但选了没反应 | 手机浏览器用的是**旧缓存页面** | 强制刷新（见下） |

> **手机显示"在线"，但电脑上明明是离线** —— v7.4 已彻底修复：
> 手机端不再自己编状态，一定会先从电脑网页取；中继重启后也不会把状态顶成"在线"。
> 若仍出现，多半是**油猴脚本还是旧版**（旧版只在状态变化时上报）：
> 按 12.3 把 `/probe.js` 整段覆盖粘贴一次，到 v7.5 即可。

**iPhone 强制刷新（清掉旧缓存）**

方法一（最彻底）：
```
设置 → Safari → 高级 → 网站数据 → 搜索你的电脑 IP → 左滑删除
然后重新打开 http://电脑IP:8765
```

方法二：长按 Safari 地址栏的刷新按钮 → 选「清除缓存并重新加载」。

**为什么早期版本点不动**

旧版的顶部控件是 `<div>` / 弹层菜单，而 iOS Safari 对**非按钮元素**的点击派发并不可靠，且弹层容易被
误触关闭。v7.4 已把顶部两个控件改为**原生 `<select>` 下拉框**（iOS 点一下就是系统选择器，最稳），
外观仍是圆角胶囊。

**自检：判断是服务问题还是缓存问题**

手机 Safari 打开：

```
http://电脑IP:8765/api/categories
```

- 能返回 JSON → 服务正常，问题是**手机页面缓存**，按上面清缓存
- 返回不了 → 服务或网络问题，看第 12.1 节

**我的手动离线被改回在线了** —— v7.4 加入了**离线守护**：探针会把你手动选的"离线"守住，
网页自己跳回在线也会被改回离线，并在中继窗口打印 `🛡️ 检测到网页把状态自动改成了「IM在线」…`。
若想关掉这个保护，把 `config.json` 里加一行 `"keep_manual_offline": false`（不写默认开启）。

### 12.12 挂起 / 恢复 / 关单点了没反应（V7.5 会自己重试并留下原因）

**第一步：先看提示**。所有动作都有回执，三个地方能看到：

| 位置 | 看什么 |
|------|--------|
| 手机页面**顶部气泡** | `挂起成功 · 已点击「挂起」` / `挂起失败 · …` |
| 手机页面**底部常驻红色条**（V7.5 新增） | 失败原因会**一直留着**（可复制），含页面上真实的按钮清单；点一下 × 关闭 |
| 中继服务窗口 | `[动作] ✅ 挂起：已点击「挂起」` / `[动作] ❌ 挂起：…` |

**V7.5 起会自动帮你想办法**（不用再手忙脚乱）：

1. 第一次没找到按钮 → 先如实回报，然后**每 0.4 秒重试一次，共 5 次**（按钮常是懒渲染，等一下就有了）；
2. 还找不到 → 自动点开 **「更多 / ⋯ / 操作」** 菜单再找一遍（很多工作台把挂起/恢复收在二级菜单里）；
3. 按钮识别范围也放宽了：**文字、aria-label、title、图标类名**（如 `el-icon-send`）都认，关键字也补全了
   （挂起/挂起工单/暂挂/暂停会话/暂停服务/搁置/休眠；恢复/恢复会话/重新接入/重新接待/继续会话/接单/接入/激活）。

**第二步：按提示分辨原因**

| 提示 | 原因 | 处理 |
|------|------|------|
| 重试 5 次仍未找到「挂起」+ 后面列了按钮名 | 页面按钮叫的是别的名字 | 把列出的名字发我，我在 `probe.js` 的 `ACTION_HANGUP` 关键字里加一个即可 |
| 未找到「恢复」按钮 | 该工单当前没有"恢复"按钮（可能已恢复/页面无此功能） | 以页面为准；也可直接在电脑上点 |
| `挂起失败 · 电脑端探针未连接` | 电脑网页关了 / 油猴脚本没跑 | 打开 `http://127.0.0.1:8765/diag` 看探针灯（见 12.2） |
| `关单未完成 · 未找到「回复并关单」按钮，页面按钮：…` | 关单按钮名不同/在菜单里 | 同上；V7.5 **会保留会话**，不会让卡片凭空消失 |
| `关单中…（等待页面确认）` 一直不变 | 页面没回报结果（探针卡住/网页被关） | 等 20 秒会自动保留会话并提示；到电脑上确认工单状态 |
| `关单失败 · 分类候选里没有匹配「XXX」的项；本层可选：…` | AI 选的分类名与页面选项对不上 | 把"本层可选"里的真实分类名填进 `config.json` 的 `close_category_options`（或修正 `close_category_path`），再重试 |

> **为什么宁可不选分类**：旧版选不中分类时会"取第一项"兜底，结果把工单选成错误的分类
> （比关不掉更糟）。V7.3 起改为**宁可不选并列出候选**，让你能一眼修正配置。

### 12.17 草稿填进去了、但「回复」按钮一直是灰的 / 点了没发出去（V7.7 实机校准）

**现象**：半自动模式 AI 起草后，回复框看起来还是空的；或者工作台的「回复」按钮一直是灰色点不动。

**原因（实机 Console dump 校准，2026-09-29）**：本工作台的回复框是 **Quill 富文本**
`div.ql-editor[contenteditable=true]`，而旧版 `composerInput()` 取的是 `.editor-composer`
里的**第一个 `input`/`textarea`** —— 在新版工作台上它抓到的是「请选择问题分类」那个输入框，
于是草稿写进了**分类框**，真编辑区一直空着（按钮自然是灰的）。

**V7.7 修法**：回复框优先 `.ql-editor`，其次其它 `contenteditable`（排除 Quill 的隐藏
`.ql-clipboard`），最后才退回 `input/textarea`；写入走 `execCommand('insertText')` +
完整事件序列（这样 Quill 才会通知页面把「回复」按钮点亮）；发送键认实机类名
`button.im-action-btn.reply-btn`（灰的不点），并保留"回车发送"兜底。

**排障一行命令**（工作台页面 Console）：`__probe.editor()`
→ 直接告诉你"抓到哪个元素、里面是不是空的"；若是只读模式会明确提示
`当前是只读模式（管理员查看全部会话时为只读模式）——请先在左侧会话列表接入/接手该工单`。

### 12.16 AI 起草好了，点发送却没发出去（V7.5 已加固）

**现象**：半自动模式下 AI 把草稿填进了回复框，但点 ↑ 没反应 / 提示"已填入，但没找到「发送」按钮"。

**原因**：工作台的发送键可能是**图标按钮（没有文字）**，或者干脆是**回车发送**；
旧版只按"文字=发送/回复"找按钮，所以点不到。

**V7.5 的发送闭环**（自动依次尝试，并在发完后**复验**）：

1. 在回复框所在容器里找发送按钮：按**文字 / aria-label / title / 图标类名（`send`、`submit`、`send-btn`…）**匹配，
   从右往左优先（发送键通常在右侧）；
2. 找不到 → 在回复框里**模拟真实回车**（keydown/keypress/keyup + `keyCode 13`）；
3. 再等 0.5 秒**复验回复框是否已清空**（清空 = 确实发出去了）；
4. 仍然没发出去 → 明确提示 `已填入内容，但没找到发送按钮、回车也没生效 —— 请在电脑上手动点发送/按回车`，
   并出现在手机底部常驻条里（可复制）。

**你要做的**：如果还发不出去，把常驻条里的那句话发我 —— 里面会带页面真实的按钮名/结构线索，我按它加规则即可。

### 12.17 手机输入框看不到长草稿（V7.5 已修）

手机聊天页的输入框已从**单行**改为**多行自适应**：

- 内容多 → 自动长高，**最多到约 1/3 屏高**（`max-height:38vh`，上限 240px）；
- 超过上限 → 输入框内部**可上下滚动翻阅**（不会把整页顶掉，也不会挡住消息区）；
- 收到 AI 草稿（`FILL_DRAFT`）或你自己输入/聚焦时都会自动重算高度；发送后自动收回单行高度。

### 12.13 手机卡片重复 / 名字都叫「玩家信息」（V7.4 已修）

| 现象 | 原因 | 现在的行为 |
|------|------|-----------|
| 9 个会话里有成对重复（名字/时间/预览都一样） | 旧版工单指纹 = `面板文本 + 首条玩家消息`；列表虚拟滚动或页面重渲染会让"首条消息"变化 → 同一工单被算成两个 → 手机端两条卡片 | 指纹只用**玩家身份**（昵称 + UID）；有工单号时再用工单号 |
| 所有卡片都叫「玩家信息」 | 右侧面板第一行是**栏目名**「玩家信息」，旧版直接拿它当玩家名 | 优先解析「昵称：XXX」；没有昵称则用 `玩家+UID后4位` |
| 聊天页看不出这个玩家是谁 | 没展示面板字段 | 聊天页新增**玩家信息卡**（默认 2 行，点一下展开全部） |

> 升级 v7.4 后**重启一次中继**（或关掉黑框再双击 `launcher.bat`），历史遗留的重复会话就会被清空。

### 12.14 电脑网页的"问题类型"下拉自己弹出来（V7.4 已修）

旧版为了给 AI 准备分类候选，**每次探针连接都会点开一次分类下拉**去读选项 —— 所以你正在打字时
它可能突然弹出来。现在改成：

1. **缓存优先**：你自己点开分类下拉时，探针顺手把选项记下来（完全无打扰）；
2. 中继**只在"还没拿到过分类"时**才请求一次，且读完**立刻收起**，不会留一个弹开的菜单；
3. 中继窗口会打印 `[分类] 已获取 N 个问题分类`，可在 `http://127.0.0.1:8765/api/categories` 核对。

若你想刷新分类候选：在电脑网页上手动点开一次「问题分类」下拉即可（探针会自动采集）。

### 12.15 自动回复节奏 / 需要人工介入 的排查（V7.4）

| 现象 | 怎么查 | 说明 |
|------|--------|------|
| 想确认"节奏"是否在跑 | `/api/diag` 看 `auto_reply.pending_gids` | 里面列出的工单就是"正在等玩家说完"的 |
| 想让某个工单立刻回 | 手机打开该会话点「✨ AI 起草」 | 手动点的不受延迟限制 |
| 想整体改成立刻回 | 手机发 `SET_AUTO_DELAY {min:0,max:0}`，或改 `config.json` 两个延迟为 0 | 改完新消息立刻排 0 秒 |
| 不想自动发开场语 | `config.json` 里 `auto_send_greeting: false` | 表格里那类开场语就不再自动发 |
| 表格里没有答案时会怎样 | 中继窗口打印 `[人工] 🙋 需要人工介入：…` | 同时：发安抚话术 → 三短一长报警 → 会话置顶 → 复制"玩家信息 + 问题总结"到剪贴板 |

### 12.11 悬浮窗不见了 / 跑到屏幕外

**先按 `Ctrl + Alt + H`** —— 这是召回热键，会把悬浮窗拉回右下角并重新置顶。

如果还是看不见，按下面的顺序排查：

| 情况 | 判断方法 | 解决 |
|------|---------|------|
| 被手动关了 | 任务管理器里**没有** `pythonw.exe` | 重新运行 `pythonw semi_runner.pyw`（或重新双击 `launcher.bat`） |
| 进程还在但看不见 | 任务管理器里**有** `pythonw.exe` | 按 `Ctrl+Alt+H`；仍不行就结束所有 `pythonw.exe` 再重开（新版会自动把位置夹回屏幕内） |
| 换了显示器/改了分辨率 | 之前位置记在了屏幕外（例如 2560 宽的屏换回 1440x900） | 新版启动时会**自动夹回屏幕内**，状态行会提示「🛠 悬浮窗原坐标在屏幕外，已自动移回」 |
| 被浏览器全屏盖住 | 浏览器按了 `F11` 全屏 | 退出全屏（`F11`）即可；普通最大化窗口盖不住置顶悬浮窗 |
| 关掉了置顶 | 标题栏 📌 变成灰色 | 按 `Ctrl+Alt+H` 召回（会重新置顶），或点 📌 打开 |
| 重复启动了两个 | 任务管理器里有**两个** `pythonw.exe` | 新版有单实例保护：再次启动会提示"已经在运行"。老版本遗留的重复进程请手动结束一个 |

**为什么会出现"跑到屏幕外"**

悬浮窗的坐标存在 `hud_pos.json` 里。以前它直接照搬旧坐标，
一旦屏幕变小（换显示器、改缩放、改分辨率），窗口就会被摆到可见区域之外——
进程活着、日志正常、热键也注册了，但人就是看不见。现在启动时会：

1. 把坐标**夹取**到屏幕可见范围内（`clamp_position`）
2. 按 DPI 缩放换算尺寸，避免 200% 缩放时文字溢出/错位
3. 提供 `Ctrl+Alt+H` 一键召回

**验证悬浮窗真的存在（进阶）**

```powershell
# 看进程
Get-CimInstance Win32_Process -Filter "Name='pythonw.exe'" | Select ProcessId,CommandLine
```

也可以在浏览器打开 `http://127.0.0.1:8765/diag`：悬浮窗与自检页读的是同一份状态，
若自检页一切正常而悬浮窗不见，那一定是**窗口位置/置顶**问题，而不是服务问题。

### 12.18 人工样本一直是 0 条（蒸馏不出东西，V8.3）

按顺序确认，全部用现成入口，不用翻日志：

| 检查 | 怎么看 | 不对就怎么办 |
|------|--------|--------------|
| 探针脚本是不是新版 | 工作台页面 Console 输入 `__probe.version()` | 不是 `8.3` 就按 12.3 重新粘贴 `/probe.js`（脚本跑在浏览器里，**只改源码文件无效**） |
| 嗅探有没有起来 | Console 输入 `__probe.demos()` 看 `captureEnabled` | 是 `false` → `__probe.config.demoCapture = true` 然后刷新页面 |
| 动作没被认出来 | `demos()` 里 `captured` 一直是 0 | 必须是**真人**点页面上的「回复」按钮、或**焦点在回复框里按回车**；点别处、Shift+回车、AI/手机代发都不会记 |
| 记为 `skipped` | `demos()` 里 `skipped` 在涨 | 说明"点了但没真发出去"（按钮是灰的 / 页面没反应）—— 嗅探会如实**不记**，先解决"发不出去"本身（见 12.16/12.17） |
| 探针在发、中继没收 | `demos()` 里 `sent` 在涨，但 `/diag` 的「人工样本」还是 0 | 确认中继是 **v8.3**（自检页顶部会写"期望 v8.3"）；旧中继不认识 `RECORD_MANUAL_DEMO` 事件，重启服务即可 |
| 只记到了测试语料 | 目录里只有 `demonstrations.test.jsonl` | 那是 `?test=1` 的假探针写的（故意隔离）；真实样本在 `demonstrations.jsonl` |

> 记得：**样本要真人发、真发出去、正文 ≥2 字**才会被记；同一条 6 秒内重复点只记一次。

> `mobile_feature_test.py` 里涉及真实调用 DeepSeek 的用例偶尔会因网络延迟超时，
> 重跑一次通常就过了（失败项每次不同即为超时特征，而非功能缺陷）。
> 其中「已有的会话不重复提醒（只认真正新出现/内容变了的）」是**既有的时序敏感用例**，
> 改动前后表现一致（旧版同样偶发），单独重跑该项即可。

### 13.4 版本管理（Git）

项目已配置好 Git：

```bash
git status                  # 看改了什么
git add .                   # 暂存
git commit -m "说明改动"     # 提交
git log --oneline -5        # 看最近提交
```

`config.json`（含密钥）已在 `.gitignore` 中，**不会被提交**。

### 13.5 升级到新版本

1. **停止服务**
2. 备份 `config.json`（密钥别丢）
3. 用新版覆盖源码：`probe.js` / `bridge_server.py` / `agent_core.py` /
   `semi_runner.pyw` / `rules_sync.py`
4. **更新油猴脚本**（每次改 `probe.js` 都必须做，方法见 12.3：
   打开 `http://127.0.0.1:8765/probe.js` 全选复制 → 油猴里全选删除 → 粘贴 → `Ctrl+S`）
5. 若 `config.json.template` 有新增配置项，对照补进你的 `config.json`
6. 启动服务 → 打开 `http://127.0.0.1:8765/diag` 确认三盏灯都绿
7. 跑一遍 13.3 的自检
