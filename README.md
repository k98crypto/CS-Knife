## 一、它是什么

一个**半自动 / 全自动的游戏客服助手**，跑在你自己电脑上：

- 从客服工作台网页**实时抓取玩家工单**
- 用 AI（DeepSeek）对照**官方规章库**生成合规回复
- 电脑上按热键即可**一键出话术**，不用手打
- 手机上能**远程看工单、改状态、代回复、一键关单**

它**不改动官方系统**，只是在浏览器里"帮你操作"，所有回复最终仍由你确认发送。

## 二、系统组成

```
┌──────────────────┐        WebSocket        ┌────────────────────┐
│  probe.js        │◄───────────────────────►│ bridge_server.py   │
│  （油猴探针）      │   ws://127.0.0.1:8765   │  （中继 + 手机网页） │
│  跑在客服工作台页   │                         │  跑在本机 8765 端口  │
└──────────────────┘                          └─────────┬──────────┘
                                                         │ 调用
         ┌───────────────────────────────────────────────┤
         │                                               │
┌────────▼─────────┐                          ┌──────────▼─────────┐
│ agent_core.py    │                          │ semi_runner.pyw    │
│ 业务大脑          │                          │ 桌面悬浮窗 + 热键    │
│ 规章库 / AI 决策  │                          │ F6 F7 F8 F9 F10    │
└────────┬─────────┘                          └────────────────────┘
         │
┌────────▼─────────┐     ┌──────────────┐     ┌────────────────────┐
│ rules.xlsx│     │ DeepSeek API │     │ Bark 推送到手机      │
│ 规章库（13 张表）  │     │ 生成回复      │     │ 疑难单 / 掉线 / 关单  │
└──────────────────┘     └──────────────┘     └────────────────────┘
```

| 文件 | 作用 |
|------|------|
| `probe.js` | 油猴脚本，抓页面数据、执行回复动作 |
| `bridge_server.py` | 中继服务，同时提供手机端网页 |
| `agent_core.py` | 规章库匹配 + AI 决策 |
| `semi_runner.pyw` | 桌面悬浮窗（热键、状态提示、结果核验） |
| `launcher.py` | 一键启动（中继 + 悬浮窗） |
| `launcher.exe` | 打包好的一键启动器（双击即用，本机产物、未入库） |
| `启动服务.vbs` | 双击启动两个服务（中继带窗口、悬浮窗静默） |
| `一键打包清理.bat` | 重新打包 `launcher.exe` 并清理中间产物 |
| `rules_sync.py` | 规章库自动同步工具 |
| `config.json` | 所有配置（**含密钥，切勿外传**） |
| `rules.xlsx` | 规章库文件 |

## 三、安装与首次配置

### 3.1 环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 / 11 |
| Python | 3.8 以上（本文档实测 3.14） |
| 浏览器 | Chrome / Edge，并安装 **Tampermonkey** 扩展 |
| 手机 | 与电脑在**同一个 WiFi / 局域网** |
| 网络 | 能访问 DeepSeek API |

### 3.2 安装依赖

在项目目录打开命令行：

```bash
pip install -r requirements.txt
```

如果下载很慢，用国内镜像：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 3.3 配置 `config.json`

用**记事本**或 VS Code 打开 `config.json`，逐项填写：

```json
{
  "port": 8765,
  "bark_key": "你的 Bark Key",
  "deepseek_api_key": "sk-你的DeepSeek密钥",

  "use_local_excel": true,
  "local_excel_path": "rules.xlsx",

  "rules_auto_sync": true,
  "rules_sync_interval_minutes": 30,
  "rules_watch_dir": "",

  "kb_retrieval_enabled": true,
  "kb_retrieval_top_k": 25,
  "kb_static_max_chars": 12000,
  "kb_entry_max_chars": 400,

  "close_category_path": ["一级分类", "二级分类"],
  "close_category_default": "其他"
}
```

**必填的两项**：

| 键 | 说明 | 不填会怎样 |
|----|------|-----------|
| `deepseek_api_key` | DeepSeek 开放平台的 API Key（`sk-` 开头） | **AI 完全不可用** |
| `bark_key` | iPhone 上 Bark App 里显示的 Key | 手机收不到推送（其他功能正常） |

> ⚠️ **安全提醒**：`config.json` 已加入 `.gitignore`，**不会被上传到 Git**。
> 但仍请勿通过微信/邮件外发这个文件。

### 3.4 准备规章库

把在线表格导出为 Excel，命名为 **`rules.xlsx`**，放到项目根目录（和 `launcher.bat` 同一层）。

> 当前规章库含 13 个工作表、800+ 条规则，系统会自动全部解析。

验证是否读取成功：

```bash
python rules_sync.py --info -v
```

### 3.5 安装油猴脚本

1. 浏览器点 Tampermonkey 图标 → **添加新脚本**
2. 全选删除模板内容
3. **打开 `http://127.0.0.1:8765/probe.js`**（推荐）→ `Ctrl+A` / `Ctrl+C` 全选复制
4. 覆盖粘贴到油猴编辑器里
5. `Ctrl + S` 保存，确认脚本已启用（状态为绿色）

> ⚠️ **请从 `http://127.0.0.1:8765/probe.js` 复制，不要直接打开项目目录里的 `probe.js` 复制。**
> 原因：仓库是公开的，`probe.js` 里的 `@match` 域名写成**占位符** `ticket.example.com`；
> 中继在响应 `/probe.js` 时会按本地 `config.json` 的 `workbench_domains` **自动注入你的真实工单域名**
> （可填多个，会展开成多行 `@match`）。所以从项目文件直接复制出来的脚本是**匹配不到工作台**的。

```json
"workbench_domains": ["你的工单域名", "备用域名（可省略）"]
```

> 加 `?download=1`（`http://127.0.0.1:8765/probe.js?download=1`）可以直接下载成文件。

脚本只会在上面配置的域名生效，不会影响其他网站。

> **粘贴后必须刷新工作台页面**，然后看页面**左下角有没有一个绿色小胶囊**
> `🟢 探针 v7.4 · 已连接`：
>
> - 有绿色胶囊 = 脚本已生效 ✅
> - 有红色/黄色胶囊 = 脚本生效了，但没连上中继（中继没启动，或还没刷新页面）
> - 完全没有胶囊 = 脚本没生效（油猴里没启用 / 域名不匹配 / 没保存成功）
>
> 这是判断"油猴到底加载了没"最快的办法（详见 12.2）。

## 四、启动与关闭

### 4.1 启动

**方式一：双击 `launcher.exe`（最省事，本机已打包好）**

**方式二：双击 `启动服务.vbs`（无黑框干扰）** —— 中继在窗口里跑（方便看日志），悬浮窗静默启动。

**方式三：双击 `launcher.bat`**（本机自带脚本，未入库；公开仓库里请用下面方式四），它会自动：

1. 检查 Python 环境与必要文件
2. 必要时自动安装依赖
3. 启动中继服务（黑框窗口）
4. 启动桌面悬浮窗

**方式四：命令行两行**（仓库自带的 `launcher.py` 与手动启动等价）

```bash
python launcher.py             # 一键（等价于下面两条）
# 或手动分两步：
python bridge_server.py        # 中继服务（保留窗口看日志）
pythonw semi_runner.pyw        # 桌面悬浮窗（无黑框）
```

启动成功会看到：

```
============================================================
[启动] IM 移动端中继与 AI 自动托管服务已启动！
手机访问: http://192.168.x.x:8765
系统自检: http://127.0.0.1:8765/diag   （探针/手机端是否在线一屏看懂）
探针脚本: http://127.0.0.1:8765/probe.js （核对油猴里那版是否最新 v7.4）
============================================================
[规章库] 自动同步已开启：每 30 分钟检查一次
[探针] ✅ 已连接 · 来源: https://你的工单域名/...
[探针] 🚀 握手成功：v7.4 · https://你的工单域名/imChat/workstation
======== Running on http://0.0.0.0:8765 ========
```

**记住那个 `http://192.168.x.x:8765` 地址**，手机要用。

上面两行 `[探针]` 日志就是"油猴脚本已生效并连上来了"的铁证；
如果只看到 `[探针] ⚠️ 已连接但未上报版本`，说明油猴里还是旧脚本，按 12.2 更新即可。

### 4.2 首次启动的防火墙提示

Windows 可能弹窗询问是否允许 Python 访问网络 —— **必须勾选「专用网络」并允许**，
否则手机连不上。

若误点拒绝，手动放行：

```
控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙
→ 找到 Python → 勾选「专用」
```

### 4.3 关闭

| 想关闭的东西 | 操作 |
|-------------|------|
| 全部服务 | 关闭「CS-WebSocket」黑框窗口 |
| 只关悬浮窗 | 点悬浮窗右上角 ✕（不影响中继服务） |
| 强制全清 | 任务管理器结束所有 `python.exe` / `pythonw.exe` |

### 4.4 开机自启（可选）

把 `launcher.exe` 或 `启动服务.vbs` 的快捷方式放进：

```
C:\Users\你的用户名\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Startup
```

## 五、电脑端日常使用

### 5.1 热键速查

在客服工作台页面按对应键即可：

| 热键 | 功能 | 使用方式 | 结果 |
|------|------|---------|------|
| **F6** | 下载媒体文件 | 复制图片/视频链接 → 按 F6 | 保存到桌面 `CS_Media` 文件夹 |
| **F7** / **F8** | 提炼工单 | 直接按（**免框选**） | 一句话总结进剪贴板 + 显示在悬浮窗 |
| **F9** | 智能解答 | 直接按（**免框选**；想指定范围也可先选中聊天区域） | AI 生成回复并**自动填入网页回复框** |
| **F10** | 公关润色 | 选中草稿/领导批示 → 按 F10 | 润色为官方话术后替换原内容 |
| **Ctrl + Alt + H** | 召回悬浮窗 | 任何时候直接按 | 悬浮窗回到右下角并重新置顶（**看不见悬浮窗时的救命键**） |
| **Ctrl + Alt + M** | 折叠/展开悬浮窗 | 直接按 | 收成一条细条 / 展开完整面板 |

> F8 与 F7 完全等价，习惯按哪个都行。
> `Ctrl+Alt+H` / `Ctrl+Alt+M` 走的是全局热键，**不依赖浏览器焦点**，
> 因此即使在别的窗口也能把悬浮窗拉回来。

### 5.2 F9 智能解答的 6 种结果

F9 是最常用的功能，它会自动判断工单状态：

| 提示 | 含义 | 你该做什么 |
|------|------|-----------|
| 👋 **【开场】** | 玩家只说"在吗/客服"没描述问题 | 直接发送已填好的开场白 |
| 📸 **【要信息】** | 问题模糊，需要截图/录屏 | 直接发送追问话术 |
| ✅ **官方解答已填入** | 正常业务问题，已给出答案 | **核对后**发送 |
| 🚪 **【超时关单】** | 客服最后发言且超 2 小时 | 可发送并关单 |
| 🚨 **【漏单补救】** | 客服只说了"正在查询"就没下文 | 已补上正解，可直接发送 |
| ⏸️ **等待玩家回复中** | 客服最后发言未满 2 小时 | 不用处理，等玩家回 |

另外两种特殊情况：
- **⚠️ 规章未收录（内部标记，玩家看不到）**：AI 判断表格里没有答案时，会在**给系统看的**第一行标注
  `【规章库未收录，请上报内部群核实】` —— **这行永远不会出现在玩家对话框里**（出站安全闸会整块删掉它）。
  系统对玩家的处理是：
  1. 给玩家发**安抚话术**：`亲爱的玩家，您的问题我已经收到啦，正在为您查询相关信息，请稍等片刻哦~`
  2. **三短一长长报警** + Bark 推送 + 手机黄色横幅
  3. 该会话**置顶**（列表最前 + 📌🙋）
  4. 自动把 **玩家信息 + 问题总结 + 处理建议** 复制到剪贴板，你直接粘去群里/工单备注即可
  （**不会**自动挂起工单、**不会**把任何内部话甩给玩家）
- **❌ AI 未返回内容(接口异常)，已阻止粘贴**：网络/密钥问题，**系统会阻止粘贴**，不会把错误信息发出去

> 💡 **F9 到底把什么发给 AI？** 就是**当前这个工单的聊天记录**（玩家发的内容 + 必要的客服发言）：
> 先看你有没有选中文字 —— 选了就用选中的；没选就**自动读当前会话**（真·免框选）。
> 生成结果优先**直接写进网页回复框**（不依赖光标位置，也不会被剪贴板内容污染）；
> 探针没连上时才退回"复制到剪贴板 + Ctrl+V"。
> **自动回复（非手动按 F9）时**还会按你的节奏走：等 1~3 分钟随机、玩家继续说话就重新计时（见 6.6）。

### 5.5 话术安全闸（玩家永远看不到"内部话"）

**铁律**：发给玩家的任何一句话里，**绝不能出现**下面这些字样 —— 违反会被玩家投诉，也可能被平台判定违规。

| 类别 | 禁词（命中即改写/删除） |
|------|------------------------|
| 内部组织 | `内部群`、`群内客服`、`群里的人工`、`群聊`、`上报`、`报备群` |
| 补偿承诺 | `补偿`、`赔偿`、`补发`（连同紧跟的金额，如"补偿您100钻石"整句换成中性说法） |
| 时间承诺 | `承诺…`、`保证…`、`一定会修复`、`48小时内修复/到账`、`马上/立刻修复` |
| 技术黑话 | `BUG`、`漏洞`、`程序错误`、`F6~F10` 等内部快捷键 |
| 内部提示 | `【规章库未收录…】` 这类内部标记（**整块删除**） |

**闸门装在哪里**（每一处"可能进玩家对话框"的文本都过闸）：

| 出口 | 说明 |
|------|------|
| AFK 自动回复 / 超时关单 | AI 文案 → 清洗后才发送 |
| 半自动草稿（填进回复框） | 同样清洗（草稿也可能被你顺手发出去） |
| 开场语 / 安抚话术 | 来自表格，但同样复核零禁词 |
| F9 / F10 直填（`/api/fill_draft`） | 清洗后才会写进网页回复框；接口会回传 `filtered` 命中项 |
| 手机端「代回复 / 关单」 | 你从草稿复制来的内容也会被清洗（清洗后为空则直接拦截并提示） |

**怎么自查**：
- 中继窗口里出现 `[安全闸] 已清洗发送内容（…）：N -> M 字` 就是它生效了；
- 出现 `[安全闸] ⚠️ 清洗后仍命中禁词：[…]` 说明还有漏网词，把那条发我，我加规则；
- `【规章库未收录…】` 这类内部提示被清空时，系统会**直接转人工**（发安抚话术 + 长报警），不会硬发一句空话给玩家。

> 出厂禁词表在 `agent_core.py` 的 `OUTBOUND_RULES` / `FORBIDDEN_OUTBOUND`，你可以自己加词。
> 回归测试 `python auto_reply_test.py`（第 7 节）+ `python mobile_feature_test.py`（第 8 节）会验证"零禁词"。

### 5.6 品牌与称谓可配置（仓库源码里不写内部词）

仓库是公开的，所以**源码里只有通用词**（`示例公司` / `客服助手` / `本游戏` / `亲爱的玩家` / `IM 系统`）。
你自己真实的公司名、产品名、游戏名、玩家尊称，全部写在**本地 `config.json` 的 `brand` 段**里（该文件不入库）：

```json
"brand": {
  "company":   "你的公司名",
  "product":   "你的产品名",
  "game":      "你的游戏名",
  "im":        "你的 IM 系统名",
  "honorific": "你对玩家的统一尊称"
}
```

生效范围：AI 提示词里的游戏名与称谓、开场语/安抚话术/兜底话术、手机端 H5 标题、自检页标题、AI 关单结束语。
**不配也能跑**（就用上面的通用词），配了就整体替换 —— 改完**重启中继与 HUD** 生效。

同理，**个人补丁库**走两条路（同名文件优先、未被 git 跟踪）：

| 文件 | 用途 | 是否入库 |
|------|------|----------|
| `patch_rules.local.txt` | 你的真实公关铁律 / 内部话术（推荐写这里） | ❌ 不入库（.gitignore） |
| `patch_rules.txt` | 仓库自带的**通用示例**，没写 local 文件时才用它 | ✅ 入库 |

> 想确认仓库里没有内部词：`git grep -nE "内部禁用词1|内部禁用词2"`（把词换成你要查的），或直接看
> `.gitignore` 里列出的"隐私/内部资料"清单 —— 规章库 xlsx、个人补丁库、内部搭建文档都不会上传。

### 6.4 IM 状态远程切换（顶部下拉框）

顶部**第一个下拉框**显示的是**电脑端网页上的真实状态**，由探针实时同步过来：

| 显示 | 含义 |
|------|------|
| 🟢 IM 在线 | 电脑端工作台显示「IM在线」 |
| 🟡 IM 忙碌 | 电脑端工作台显示「IM忙碌」 |
| 🔴 IM 离线 | 电脑端工作台显示「IM离线」（手动挂的还是掉线的都算） |
| ⏳ 正在获取… | **刚打开手机页：正在问电脑网页要真实状态**（约 1 秒内出结果） |
| ⚫ 电脑未连接 | **电脑端网页已关闭 / 探针掉线** —— 此时远程操作无效 |

> 手机端**不会自己编一个「在线」给你看**：打开页面的瞬间会先显示 ⏳ 正在获取…，
> 从电脑网页问到真实状态后才显示；关掉电脑网页后会变成 ⚫ 电脑未连接。

点下拉框即可远程切换：

| 选 | 效果 |
|----|------|
| 🟢 IM 在线 | 电脑端切到在线；**若正在报警会自动消除警报** |
| 🟡 IM 忙碌 | 电脑端切到忙碌 |
| 🔴 IM 离线 | 电脑端切到离线（手动离线，不触发警报） |

> - 下班前在手机上选「IM 离线」即可，不用回工位
> - 若显示 ⚫ 电脑未连接，点按会提示「电脑端未连接，请先打开客服工作台」
> - **切换/远程操作都需要电脑端网页开着**（探针必须在线）
> - **手动离线会被守住**：你手动挂了离线之后，哪怕工作台自己跳回"在线"（很多 IM 在窗口
>   重新获得焦点时会自动上线），探针会立刻把它改回离线，手机端也会跟着回到 🔴 离线。
>   真想在电脑上改回在线，直接点工作台的状态即可（人的点击永远优先）。

|------|------|-----------|
| ✋ **手动** | **只提醒新消息，AI 不自动起草** | 想完全自己写时（把"AI 自动起草"关掉） |
| 🤖 **半自动**（默认） | AI 自动起草推到回复框，**等你确认发送** | 日常 |
| 🚀 **AFK 全自动** | AI **直接发送**给玩家，人完全不参与 | 短期离开工位 |

AFK 模式下：

- 正常问题 → 直接回复玩家
- 超时工单 → 直接回复并关单
- **规章未收录** → 自动挂起 + 推 Bark 提醒你介入

> ⚠️ 建议只在短期离开工位时开启 AFK；切回「手动 / 半自动」即刻生效（面板上有 ✓ 标出当前档位）。

> **电脑小窗也能切**：悬浮窗标题栏的 `🤖半自动 / 🚀AFK / ✋手动` 按钮（点一下循环，见 5.3）。
> **两边冲突时以手机端为准**：手机端改过之后的 10 分钟内（`mobile_mode_priority_sec` 可调），
> 小窗的切换会被拒绝并提示；小窗每 5 秒跟随中继显示，所以手机端一改，小窗立刻跟着变。
> **默认永远是半自动**：AI 只把草稿填进输入框，**不发送**。

### 6.6 自动回复节奏（V7.4 新增：不秒回、等人说完）

> 客服反馈："玩家一发就秒回，像脚本、又费 token、还打断玩家说话。"

| 环节 | 现在的行为 |
|------|-----------|
| 玩家**第一次**发言 | **立刻发一条开场语**，严格取自表格（话术库「没有描述问题/直接转人工」那一类）；表格缺了才用兜底句 |
| 之后 | **不秒回**：等 **1~3 分钟随机**（`auto_reply_delay_min_sec` / `max` 可调）；期间玩家再来消息就**重新计时**，确认他不说了才回复 |
| 该不该回 | 只有"**玩家最后发言**且这条还没被回过"才回 —— 客服最后发言时绝不抢话 |
| 发给 AI 的记录 | 程序自行判断：**丢掉玩家开口之前的客服发言**；玩家之后的客服发言只保留最近 2 条（省 token） |
| AI 判为「规章库没收录」 | 先给玩家发这句安抚：`亲爱的玩家，您的问题我已经收到啦，正在为您查询相关信息，请稍等片刻哦~`，然后**长报警** + **该会话置顶** + **自动把玩家信息和问题总结复制到剪贴板**（**不会**自动挂起工单） |
| 手动 / 半自动 / AFK | ✋手动 = 只提醒不起草；🤖半自动 = AI 起草到回复框；🚀AFK = 直接回复。三档都能享受上面的节奏控制 |

**手机上主动点「✨ AI 起草」不受延迟限制**（你点的就是立刻要），但也受"手动模式"约束。

> 💡 想临时改成"立刻回"：手机端可调 `SET_AUTO_DELAY`（例如 0~0），或把 `config.json` 里
> `auto_reply_delay_min_sec` / `auto_reply_delay_max_sec` 都设成 0。

### 6.7 三种提示音怎么区分

| 声音 | 场合 | 特征 |
|------|------|------|
| 叮~咚~（桌上"叮咚"/手机双音） | **玩家发来新消息** | 两个短促正弦音，清脆 |
| 连续警笛（锯齿波，会一直响） | **IM 异常掉线**（VPN/网络断） | 1000ms 一次持续循环 + 手机全屏红层 |
| **三短一长**（手机三声方波；电脑 700Hz×3 + 500Hz 长音） | **需要人工介入**（表格里没有答案，已发安抚话术） | 只响一轮，同时自动复制玩家信息+问题总结 |

### 6.8 手机端功能小结

| 功能 | 位置 |
|------|------|
| 看所有玩家会话 | 主页 |
| 未读红点 | 会话名后的红点 |
| 远程上下班 | 顶部**第一个下拉框**（IM 状态） |
| 切手动 / 半自动 / AFK | 顶部**第二个下拉框**（回复模式） |
| 看中继 / 探针是否在线 | 顶部小圆点状态条（中继 · 电脑探针 · 会话数） |
| 需人工的会话 | 列表最前 + 📌🙋 标记 + 顶部黄色横幅（点"知道了"消警） |
| 代回复 | 聊天页输入框 + ↑ |
| AI 起草 / 挂起 / 恢复 / 关单 | 聊天页操作栏 |
| 接异常警报 | 全屏红色浮层 + 静音按钮 |
| 界面不卡在旧数据 | 锁屏/切回来自动刷新（无需操作） |

## 七、规章库自动更新

线上规章一改，**AI 答复必须跟着变**。系统提供三种更新方式，**都不需要表格 API 权限**。

### 7.1 方式一：监听目录（推荐）

**一次性配置**：在 `config.json` 里指定你导出 Excel 的目录

```json
"rules_watch_dir": "C:\\Users\\你的用户名\\Documents\\表格导出",
"rules_sync_interval_minutes": 30
```

**以后每次更新只需两步**：

1. 在线表格 → 导出为 Excel
2. 把文件丢进那个目录

系统每 30 分钟检查一次，发现有更新会自动：
覆盖 → 备份旧文件 → **热重载知识库** → 发 Bark 通知

**全程不用重启服务。**

### 7.2 方式二：手动覆盖（最简单）

直接把新的 `rules.xlsx` 拖到项目根目录覆盖旧的即可。

系统会在**下次处理工单时自动识别并重载**（按文件修改时间判断），同样不用重启。

### 7.3 方式三：直链拉取

如果你们有能直接返回 Excel 的下载链接：

```json
"rules_sync_url": "https://你们的地址/export.xlsx"
```

系统会定时下载 → 校验 → 备份 → 替换（坏文件会被拒绝，不会污染知识库）。

### 7.4 后台常驻同步（可选）

不想让中继服务管这件事，可以单独挂一个：

```bash
python rules_sync.py --watch        # 常驻，前台可见
python rules_sync.py --once         # 只跑一次（适合挂 Windows 任务计划）
```

挂任务计划：`任务计划程序 → 创建基本任务 → 每天 → 操作填 python rules_sync.py --once`

### 7.5 检查同步状态

```bash
python rules_sync.py --info -v
```

或看中继服务的黑框窗口，更新时会出现：

```
[规章库] 从监听目录更新: 已更新
[规章库] 已重载：常驻 11482 字符 / 检索池 713 条 / 共 843 条 / 13 张表
```

### 7.6 关于知识库如何进入 AI

系统不会把 800 多条规则全塞给 AI（那会超长且昂贵），而是：

| 类型 | 处理方式 |
|------|---------|
| **小表**（关单优先级、账号、已知BUG 等） | **常驻**每次请求 |
| **大表**（631 条 FAQ 等） | 按当前工单内容**检索最相关的 25 条**再送入 |

所以无论工单问什么，相关规则都能命中，且 token 占用稳定。

### 7.7 回滚

每次覆盖前会备份旧文件：

```
rules.xlsx          ← 当前
rules.xlsx.bak      ← 上一版
```

出问题就把 `.bak` 改名回去即可。

## 八、AI 一键回复并关单

### 8.1 什么时候用

玩家问题已经解答完、不需要再等待时 —— 一条命令完成「选分类 + 写结束语 + 回复 + 关单」。

### 8.2 操作步骤

1. 手机进入该玩家聊天页
2. 点 **🤖 AI回复并关单**
3. 弹窗确认 → 点「确定」
4. 底部提示 `AI 正在生成结束语…`
5. 完成后提示 `已回复并关单 · 分类：xxx`
6. **该会话自动从列表消失**

### 8.3 它到底做了什么

```
你点按钮
   ↓
后端把工单聊天记录交给 AI
   ↓
AI 同时产出两样东西：
   ① 问题分类（从页面真实分类里选，如「充值问题」）
   ② 给玩家的结束语（已过滤敏感词、统一称谓）
   ↓
下发给电脑端探针执行：
   填入结束语 → 选中对应问题分类 → 点击「回复并关单」
   ↓
从手机列表移除该会话 + 推送 Bark 留痕
```

### 8.4 分类是怎么确定的（重要）

系统**不会凭空编造分类**，按优先级取：

| 顺序 | 来源 |
|------|------|
| 1 | 探针从网页**级联选择器**读到的真实分类（只读，不会误点） |
| 2 | `config.json` 里你手工配置的 `close_category_options` |
| 3 | 兜底用 `close_category_default`（默认「其他」） |

**查看探针抓到了哪些分类**（浏览器打开）：

```
http://192.168.x.x:8765/api/categories
```

若返回 `options` 为空，说明探针没读到分类选择器 —— 请先在电脑上打开一个工单（
让页面渲染出「问题分类」下拉框），然后重新访问。

若 AI 选的分类和你们的不一致，把正确分类名填进配置：

```json
"close_category_options": ["登录问题", "充值未到账", "游戏异常", "画面卡顿", "其他"]
```

同时确认分类层级路径与页面一致：

```json
"close_category_path": ["一级分类的实际名称", "二级分类的实际名称"]
```

### 8.5 安全保证

| 情况 | 结果 |
|------|------|
| AI 接口异常 / 无返回 | ❌ 提示失败，**会话不会被删除** |
| 电脑端探针掉线 | ❌ 提示「电脑端探针未连接，无法关单」，**不删会话** |
| 分类没匹配到 | 自动落到「其他」或页面第一项，**关单不会卡住** |

> 所有关单动作都会推一条 Bark 通知，留痕可查。

## 九、异常掉线警报

### 9.1 会发生什么

当探针检测到工作台显示 **IM离线**（VPN 掉线 / 网络断开）时：

| 位置 | 表现 |
|------|------|
| 电脑端 | **持续警报音** + 悬浮窗状态变红 |
| 手机端 | **全屏红色浮层** + 手机也响警报音 |
| 手机通知 | 收到 Bark「🚨 异常掉线警报」 |

### 9.2 怎么消除

任选一种：

| 方式 | 操作 |
|------|------|
| 手机静音 | 红色浮层上点 **「点击静音并忽略」** |
| 手机恢复 | 顶部状态按钮 → 切到 **🟢 IM 在线**（自动清警报） |
| 电脑恢复 | 手动把工作台切回「IM在线」（探针自动检测并解除） |

### 9.3 为什么不会重复轰炸

- 探针只在**状态发生变化**时上报一次（不会每 2 秒重发）
- 后端处理后会回执确认，探针停止重复上报

### 9.4 手动离线不报警（并且会被守住）

你自己在工作台点「IM离线」（下班）**不会**触发警报 ——
探针能区分「手动离线」与「异常掉线」。

而且从 v7.4 起，**手动离线会被守住**：工作台自己跳回「IM在线」（很多 IM 在你切窗口、
页面重新获得焦点时会自动上线）时，探针会立刻把它改回「IM离线」，手机端也始终显示 🔴 离线；
中继服务重启也不会把状态变成在线。日志里能看到：

```
🛡️ [探针] 检测到网页把状态自动改成了「IM在线」，按你的手动离线设置改回「IM离线」（第 1 次）
```

> 你自己点「IM在线 / IM忙碌」永远优先（1.5 秒内不会被扳回）。
> 若确实不想被守护（想让手机端完全跟随网页），把 `config.json` 的 `keep_manual_offline` 设为 `false`。

## 十一、接口与协议

> 用于排障和二次开发，日常使用不需要看这一节。

### 11.1 HTTP 接口

| 地址 | 用途 |
|------|------|
| `http://IP:8765/` | 手机端网页 |
| `http://IP:8765/diag` | **系统自检页**（中继 / 探针 / 手机端 / 知识库一屏看懂，每 5 秒自动刷新） |
| `http://IP:8765/api/diag` | 同上的 JSON 版（供脚本/悬浮窗读取） |
| `http://IP:8765/probe.js` | **最新探针脚本全文**（用来核对油猴里那版是否最新）；加 `?download=1` 直接下载 |
| `http://IP:8765/api/ticket` | 当前工单数据（F7 提炼用） |
| `http://IP:8765/api/categories` | 已抓取的问题分类 + 分类配置 |
| `POST http://IP:8765/api/fill_draft` | 把文案直接写进网页回复框（F9/F10 免框选走这里，body: `{"content":"…"}`） |
| `http://IP:8765/api/alerts` | 需要人工介入的告警队列（桌面 HUD / 脚本读取） |
| `POST http://IP:8765/api/alerts/ack` | 确认告警（body: `{"ids":[…]}`；不传 ids = 清空） |
| `POST http://IP:8765/api/mode` | 电脑小窗切回复模式（body: `{"mode":"manual|semi|afk","source":"desktop"}`；手机端优先时返回 `ok:false`） |

在电脑浏览器打开这些地址，可快速确认服务是否正常。
**排障时第一个该打开的永远是 `/diag`**（或 `/api/diag`），它能直接告诉你"谁没在线"。

`/api/diag` 里几个关键字段：

| 字段 | 含义 |
|------|------|
| `probe.online` | 油猴脚本是否连上（`false` = 脚本没跑起来） |
| `probe.version` / `probe.version_reported` | 脚本版本；**连上了但 version 为空 = 油猴里是旧脚本** |
| `probe.page` | 探针当前所在页面（可识破"开错页面/多开"） |
| `probe.last_seen_sec` | 最近一次心跳距今多少秒 |
| `mobile.online_clients` | 手机端在线连接数 |
| `im.status` / `im.status_text` | 手机端顶部下拉框当前显示的 IM 状态（1在线/2忙碌/3离线） |
| `im.known` | **是否已从电脑网页核实**（`false` 时手机端显示「正在获取…」，不会假装在线） |
| `im.manual` | 该状态是否来自客服手动选择（配合离线守护） |
| `auto_reply.delay_min_sec` / `delay_max_sec` | 当前"玩家说完后等多久再回"的区间（秒） |
| `auto_reply.pending` / `pending_gids` | 正在排队等玩家说完的会话数 / 工单号（一眼看出节奏是否在生效） |
| `alerts` / `alerts_count` | 需要人工介入的告警（HUD 就是读这个播长报警） |
| `ticket.conversations` | 当前识别的会话数 |
| `kb.total_rows` | 知识库总条目数 |

### 11.2 探针 → 后端（事件）
| 事件 | 含义 |
|------|------|
| `PROBE_HELLO` | 连上即发的握手（含版本/页面地址，供 `/api/diag` 自检） |
| `PROBE_HEARTBEAT` | 每 30 秒一次心跳（刷新"最近心跳"，证明脚本还活着） |
| `HEADERS_SYNC` | 上报拦截到的认证头（去重存储，不广播） |

| **电脑网页"问题类型"下拉老是自己跑下来** | 旧版每次探针连接都去点开分类下拉读选项 | v7.4 已修：缓存优先 + 只在没拿到过分类时请求 + 读完收起（见 12.14） |
| **手机顶部下拉太丑/有框/卡顿** | 旧版用原生 `<select>` | v7.4 改为自绘按钮 + 底部选择面板；请清缓存重载手机页 |

### 12.2 手机显示「暂无会话」/ 怀疑脚本没生效

**第一步：打开自检页 `http://127.0.0.1:8765/diag`**（电脑浏览器，会每 5 秒自动刷新）。

| 自检页显示 | 说明 | 处理 |
|-----------|------|------|
| 探针 🔴 未连接 | 油猴脚本没跑起来 | 见下面第 2 步 |
| 探针 🟡 已连接 · 未上报版本（旧脚本） | 脚本是旧版（< v7.4），新功能都没有 | 按 12.3 更新脚本 |
| 探针 🟢 已连接 · v7.4，但会话数 0 | 脚本正常，只是**没打开工单** | 在工作台里点开一个工单 |
| 中继 🔴 | 服务没跑 | 重启 `bridge_server.py` |

**第二步：确认脚本是否加载**（工作台页面按 `F12` 打开控制台）：

```
🚀 [工单探针 V7.3] 真实靶点定位系统与防暴雷机制已就绪！
✅ [探针] WebSocket 连接成功
```

更直观的办法：**看页面左下角有没有绿色小胶囊** `🟢 探针 v7.4 · 已连接`

| 看到什么 | 结论 |
|---------|------|
| 🟢 胶囊 | 一切正常 ✅ |
| 🟡/🔴 胶囊 | 脚本生效了，但没连上中继 → 确认 `bridge_server.py` 在跑，然后**单击胶囊立即重连** |
| 完全没有胶囊 | 脚本没生效 → Tampermonkey 里没启用 / 没保存 / 页面没刷新 |
| 控制台报 `SyntaxError: Missing catch or finally after try` | **油猴里是残缺的旧脚本**（复制粘贴被截断）→ 按 12.3 整段重新覆盖 |

**第三步：确认中继服务**

```
http://127.0.0.1:8765/diag      # 能看到自检页 = 服务正常
```

**第四步：确认已打开工单** —— 探针只在「IM 工作台 + 已打开具体工单」时抓取消息。

> 控制台里随时可以自查：输入 `__probe.status()` 回车，
> 会打印版本、连接状态、胶囊状态；`__probe.reconnect()` 可手动重连。

### 12.3 手机只有一个玩家 / 旧会话被顶掉 / 要用最新脚本

**这是旧版探针的已知问题**（旧版把所有工单都写成同一个 ID）。

**解决：更新油猴脚本**

1. 浏览器打开 `http://127.0.0.1:8765/probe.js`（这就是项目里最新的脚本全文）
2. 全选复制（`Ctrl+A` → `Ctrl+C`）
3. Tampermonkey → 你的探针脚本 → **全选删除** → 粘贴
4. `Ctrl+S` 保存 → **刷新工作台页面**

**怎么确认更新成功**：页面左下角出现 `🟢 探针 v7.4 · 已连接`，
并且 `http://127.0.0.1:8765/diag` 的探针版本变成 `v7.4`（不再显示"未上报版本"）。

验证多工单隔离：打开两个不同玩家的工单，手机主页应能看到**两个独立会话**。

> ⚠️ 只把新版内容**追加**到旧脚本后面是**不行**的（会出现两个探针抢同一连接）。
> 必须先全选删除再粘贴。

### 12.4 AI 不回复 / 提示「接口异常」

| 检查项 | 方法 |
|--------|------|
| API Key 是否正确 | `config.json` 的 `deepseek_api_key` 是否 `sk-` 开头且无空格 |
| 账户是否有余额 | 登录 DeepSeek 开放平台查看 |
| 网络是否通 | 浏览器打开 `https://api.deepseek.com` |
| 是否被 VPN 干扰 | 尝试关闭 VPN 或换网络 |

> **重要**：AI 失败时系统**不会**把错误信息发出去 ——
> F9 会提示「❌ AI 未返回内容（接口异常），已阻止粘贴」，这是**保护机制**，不是 bug。

### 12.5 F9 / F10 没反应

| 原因 | 解决 |
|------|------|
| 没选中文本 | F9/F10 需要先在页面上**选中**工单聊天区域 |
| 热键被其他软件抢 | 关闭截图工具/输入法冲突键；或**以管理员身份**运行 `launcher.bat` |
| 悬浮窗没启动 | 看任务管理器是否有 `pythonw.exe` |
| 抓取失败 | 悬浮窗会显示「⚠️ 拦截: 未选中文本或选区为空」 |

### 12.6 关单后分类不对

1. 浏览器打开 `http://127.0.0.1:8765/api/categories`
2. 看 `options` 里的一级分类**是否与你们页面一致**
3. 不一致或为空 → 在 `config.json` 手工指定：
   ```json
   "close_category_options": ["登录问题", "充值未到账", "游戏异常", "其他"]
   ```
4. 同时把真实的层级名称填进：
   ```json
   "close_category_path": ["实际一级分类名", "实际二级分类名"]
   ```

### 12.7 规章库改了但 AI 还按旧的答

```bash
python rules_sync.py --info -v     # 看当前知识库状态与文件时间
python rules_sync.py --once        # 手动跑一次，看有无报错
```

### 12.8 服务窗口一闪就退出

| 原因 | 排查 |
|------|------|
| 端口被占用 | `netstat -ano \| findstr 8765` 找到并结束占用进程，或改 `config.json` 的 `port` |
| 依赖缺失 | `pip install -r requirements.txt` 看报错 |
| 看具体错误 | 在项目目录执行 `python bridge_server.py`，错误会显示在窗口里 |

### 12.9 手机界面卡在几分钟前的状态

系统已内置自动处理：锁屏/切后台回来会**自动重连 + 主动补拉快照**，
WebSocket 心跳 30 秒可及时发现假连接。若仍异常，下拉刷新手机页面即可。

### 12.10 手机顶部下拉框点不动 / 状态不对

**第一步：先看下拉框上写的是什么**

| 下拉框显示 | 说明 | 处理 |
|---------|------|------|
| ⚫ **电脑未连接** | 电脑端网页没开着 / 探针掉线 | 打开电脑上的客服工作台页面即可（此时点按会提示原因，不是"坏了"） |
| ⏳ **正在获取…** | 刚打开手机页，正在问电脑网页要真实状态 | 等 1 秒；若一直不变 → 电脑端网页/探针没在线（见 12.1） |
| 🟢/🟡/🔴 但选了没反应 | 手机浏览器用的是**旧缓存页面** | 强制刷新（见下） |

> **手机显示"在线"，但电脑上明明是离线** —— v7.4 已彻底修复：
> 手机端不再自己编状态，一定会先从电脑网页取；中继重启后也不会把状态顶成"在线"。
> 若仍出现，多半是**油猴脚本还是旧版**（旧版只在状态变化时上报）：
> 按 12.3 把 `/probe.js` 整段覆盖粘贴一次，到 v7.4 即可。

**iPhone 强制刷新（清掉旧缓存）**

方法一（最彻底）：
```
设置 → Safari → 高级 → 网站数据 → 搜索你的电脑 IP → 左滑删除
然后重新打开 http://电脑IP:8765
```

方法二：长按 Safari 地址栏的刷新按钮 → 选「清除缓存并重新加载」。

**为什么早期版本点不动**

旧版的顶部控件是 `<div>` / 弹层菜单，而 iOS Safari 对**非按钮元素**的点击派发并不可靠，且弹层容易被
误触关闭。v7.4 已把顶部两个控件改为**原生 `<select>` 下拉框**（iOS 点一下就是系统选择器，最稳），
外观仍是圆角胶囊。

**自检：判断是服务问题还是缓存问题**

手机 Safari 打开：

```
http://电脑IP:8765/api/categories
```

- 能返回 JSON → 服务正常，问题是**手机页面缓存**，按上面清缓存
- 返回不了 → 服务或网络问题，看第 12.1 节

**我的手动离线被改回在线了** —— v7.4 加入了**离线守护**：探针会把你手动选的"离线"守住，
网页自己跳回在线也会被改回离线，并在中继窗口打印 `🛡️ 检测到网页把状态自动改成了「IM在线」…`。
若想关掉这个保护，把 `config.json` 里加一行 `"keep_manual_offline": false`（不写默认开启）。

### 12.12 挂起 / 恢复 / 关单点了没反应（V7.3 起会告诉你怎么回事）

**第一步：先看提示**。V7.3 起所有动作都有回执，两种地方能看到：

| 位置 | 看什么 |
|------|--------|
| 手机页面顶部气泡 | `挂起成功 · 已点击「挂起」` / `挂起失败 · 未找到「挂起」按钮，页面上的按钮：转交他人/结束会话` |
| 中继服务窗口 | `[动作] ✅ 挂起：已点击「挂起」` / `[动作] ❌ 挂起：未找到…` |

**第二步：按提示分辨原因**

| 提示 | 原因 | 处理 |
|------|------|------|
| 未找到「挂起」按钮 + 后面列了按钮名 | 页面按钮叫别的名字（如"转交他人""结束会话""暂停服务"） | 把列出的名字发我，我在 `probe.js` 的 `ACTION_HANGUP` 关键字里加一个即可 |
| 未找到「恢复」按钮 | 该工单当前没有"恢复"这个按钮（可能已经恢复过了/页面无此功能） | 以页面为准；也可直接在电脑上点 |
| `挂起失败 · 电脑端探针未连接` | 电脑网页关了 / 油猴脚本没跑 | 打开 `http://127.0.0.1:8765/diag` 看探针灯（见 12.2） |
| `关单失败 · 分类候选里没有匹配「XXX」的项；本层可选：…` | AI 选的分类名与页面选项对不上 | 把"本层可选"里的真实分类名填进 `config.json` 的 `close_category_options`（或修正 `close_category_path`），再重试 |
| `关单成功 · 已选择分类：游戏BUG` 但工单没关 | 页面还需要额外确认（二次弹窗/必填项） | 电脑上手动补完最后一次点击 |

> **为什么宁可不选分类**：旧版选不中分类时会"取第一项"兜底，结果把工单选成错误的分类
> （比关不掉更糟）。V7.3 改为**宁可不选并列出候选**，让你能一眼修正配置。

### 12.13 手机卡片重复 / 名字都叫「玩家信息」（V7.4 已修）

| 现象 | 原因 | 现在的行为 |
|------|------|-----------|
| 9 个会话里有成对重复（名字/时间/预览都一样） | 旧版工单指纹 = `面板文本 + 首条玩家消息`；列表虚拟滚动或页面重渲染会让"首条消息"变化 → 同一工单被算成两个 → 手机端两条卡片 | 指纹只用**玩家身份**（昵称 + UID）；有工单号时再用工单号 |
| 所有卡片都叫「玩家信息」 | 右侧面板第一行是**栏目名**「玩家信息」，旧版直接拿它当玩家名 | 优先解析「昵称：XXX」；没有昵称则用 `玩家+UID后4位` |
| 聊天页看不出这个玩家是谁 | 没展示面板字段 | 聊天页新增**玩家信息卡**（默认 2 行，点一下展开全部） |

> 升级 v7.4 后**重启一次中继**（或关掉黑框再双击 `launcher.bat`），历史遗留的重复会话就会被清空。

### 12.14 电脑网页的"问题类型"下拉自己弹出来（V7.4 已修）

旧版为了给 AI 准备分类候选，**每次探针连接都会点开一次分类下拉**去读选项 —— 所以你正在打字时
它可能突然弹出来。现在改成：

1. **缓存优先**：你自己点开分类下拉时，探针顺手把选项记下来（完全无打扰）；
2. 中继**只在"还没拿到过分类"时**才请求一次，且读完**立刻收起**，不会留一个弹开的菜单；
3. 中继窗口会打印 `[分类] 已获取 N 个问题分类`，可在 `http://127.0.0.1:8765/api/categories` 核对。

若你想刷新分类候选：在电脑网页上手动点开一次「问题分类」下拉即可（探针会自动采集）。

### 12.15 自动回复节奏 / 需要人工介入 的排查（V7.4）

| 现象 | 怎么查 | 说明 |
|------|--------|------|
| 想确认"节奏"是否在跑 | `/api/diag` 看 `auto_reply.pending_gids` | 里面列出的工单就是"正在等玩家说完"的 |
| 想让某个工单立刻回 | 手机打开该会话点「✨ AI 起草」 | 手动点的不受延迟限制 |
| 想整体改成立刻回 | 手机发 `SET_AUTO_DELAY {min:0,max:0}`，或改 `config.json` 两个延迟为 0 | 改完新消息立刻排 0 秒 |
| 不想自动发开场语 | `config.json` 里 `auto_send_greeting: false` | 表格里那类开场语就不再自动发 |
| 表格里没有答案时会怎样 | 中继窗口打印 `[人工] 🙋 需要人工介入：…` | 同时：发安抚话术 → 三短一长报警 → 会话置顶 → 复制"玩家信息 + 问题总结"到剪贴板 |
| 报警一直重复响 | 桌面端会自动 ack（响一轮）；手机点横幅「知道了」 | 同一条告警只响一次 |
| 想确认开场语来自表格 | 看中继窗口 `[开场] 已按表格发送开场语：…`；对照 `费话术库`「没有描述问题」那一行 | 表格里没有时才用兜底句 |

### 12.11 悬浮窗不见了 / 跑到屏幕外

**先按 `Ctrl + Alt + H`** —— 这是召回热键，会把悬浮窗拉回右下角并重新置顶。

如果还是看不见，按下面的顺序排查：

| 情况 | 判断方法 | 解决 |
|------|---------|------|
| 被手动关了 | 任务管理器里**没有** `pythonw.exe` | 重新运行 `pythonw semi_runner.pyw`（或重新双击 `launcher.bat`） |
| 进程还在但看不见 | 任务管理器里**有** `pythonw.exe` | 按 `Ctrl+Alt+H`；仍不行就结束所有 `pythonw.exe` 再重开（新版会自动把位置夹回屏幕内） |
| 换了显示器/改了分辨率 | 之前位置记在了屏幕外（例如 2560 宽的屏换回 1440x900） | 新版启动时会**自动夹回屏幕内**，状态行会提示「🛠 悬浮窗原坐标在屏幕外，已自动移回」 |
| 被浏览器全屏盖住 | 浏览器按了 `F11` 全屏 | 退出全屏（`F11`）即可；普通最大化窗口盖不住置顶悬浮窗 |
| 关掉了置顶 | 标题栏 📌 变成灰色 | 按 `Ctrl+Alt+H` 召回（会重新置顶），或点 📌 打开 |
| 重复启动了两个 | 任务管理器里有**两个** `pythonw.exe` | 新版有单实例保护：再次启动会提示"已经在运行"。老版本遗留的重复进程请手动结束一个 |

**为什么会出现"跑到屏幕外"**

悬浮窗的坐标存在 `hud_pos.json` 里。以前它直接照搬旧坐标，
一旦屏幕变小（换显示器、改缩放、改分辨率），窗口就会被摆到可见区域之外——
进程活着、日志正常、热键也注册了，但人就是看不见。现在启动时会：

1. 把坐标**夹取**到屏幕可见范围内（`clamp_position`）
2. 按 DPI 缩放换算尺寸，避免 200% 缩放时文字溢出/错位
3. 提供 `Ctrl+Alt+H` 一键召回

**验证悬浮窗真的存在（进阶）**

```powershell
# 看进程
Get-CimInstance Win32_Process -Filter "Name='pythonw.exe'" | Select ProcessId,CommandLine
```

也可以在浏览器打开 `http://127.0.0.1:8765/diag`：悬浮窗与自检页读的是同一份状态，
若自检页一切正常而悬浮窗不见，那一定是**窗口位置/置顶**问题，而不是服务问题。

### 13.1 需要备份的东西

| 文件 | 重要性 | 说明 |
|------|--------|------|
| `config.json` | ⭐⭐⭐ | 含 API 密钥与 `brand` 品牌称谓，**丢失需重配** |
| 规章库 xlsx | ⭐⭐⭐ | 你在 `local_excel_path` 里指定的那个文件（默认 `rules.xlsx`），可从在线表格重新导出 |

| `patch_rules.txt` | ⭐ | 仓库自带的通用示例（只有没写 local 文件时才生效） |
| 修改过的源码 | ⭐⭐ | 建议用 Git 管理（见 13.4） |

> 上面标 ⭐⭐⭐/⭐⭐ 的文件都在 `.gitignore` 的"隐私/内部资料"清单里 —— **git 不会上传它们**，
> 所以换电脑/重装时只能靠这份备份，别只依赖仓库。

一键备份（PowerShell）：

```powershell
$d = "备份\$(Get-Date -Format yyyyMMdd)"
New-Item -ItemType Directory -Force -Path $d | Out-Null
Copy-Item config.json, patch_rules.local.txt $d -ErrorAction SilentlyContinue
Copy-Item (Get-ChildItem *.xlsx | Select-Object -First 1) $d -ErrorAction SilentlyContinue
```


### 13.5 升级到新版本

1. **停止服务**
2. 备份 `config.json`（密钥别丢）
3. 用新版覆盖源码：`probe.js` / `bridge_server.py` / `agent_core.py` /
   `semi_runner.pyw` / `rules_sync.py`
4. **更新油猴脚本**（每次改 `probe.js` 都必须做，方法见 12.3：
   打开 `http://127.0.0.1:8765/probe.js` 全选复制 → 油猴里全选删除 → 粘贴 → `Ctrl+S`）
5. 若 `config.json.template` 有新增配置项，对照补进你的 `config.json`
6. 启动服务 → 打开 `http://127.0.0.1:8765/diag` 确认三盏灯都绿
7. 跑一遍 13.3 的自检
